# 目的

共通暦エンジンは、御定術数システム全体で利用する
暦計算専用ライブラリである。

本エンジンは排盤を行わない。

排盤に必要な暦情報のみを返す。

---

# 入力

基本入力は

・年月日
・時分秒（秒は任意、既定 0）
・タイムゾーン（IANA 名。未指定時は `"Asia/Tokyo"`）

とする。

所在地情報（経度・緯度）は `CalendarInput` で受け取れるが、**現行実装では未使用**。

`year..second` は指定タイムゾーンの**壁時計時刻**として解釈する。

---

# 出力

共通暦エンジンは次の情報を返す（型は `src/lib/calendar/types.ts` の `CalendarResult`）。

・UTC（ISO 8601 文字列）
・ユリウス日（UT ベース）
・ΔT（TT − UT、秒）
・太陽黄経（度、0〜360）
・節気（節気名。`solarTerm: string`）
・節入り時刻（節入り瞬間の UTC ISO 8601 文字列。`solarTermDateTime: string`）
・年干支
・月干支
・日干支
・時干支

`solarTermEntered: boolean` は採用しない（[05_CalendarEngine_API.md](./05_CalendarEngine_API.md) 参照）。

---

# 行わない処理

共通暦エンジンでは次の処理は行わない。

・七政四餘の排盤
・奇門遁甲の排盤
・八門配置
・九星配置
・八神配置
・格局判定

# モジュール構成（実装）

`src/lib/calendar/`

| ファイル | 役割 |
|---|---|
| `index.ts` | 公開窓口。`calculate` と型・定数のみ再 export |
| `calendarEngine.ts` | `calculate()` 本体。`julian → solarTerm → eto` を統合する薄い調整層 |
| `julian.ts` | 壁時計 → UTC 正規化、Julian Day、ΔT |
| `solarTerm.ts` | 太陽黄経・節気名・節入り時刻の逆算 |
| `eto.ts` | 節入り境界での年月日時の干支計算（共通暦エンジン用の新規実装） |
| `types.ts` | `CalendarInput` / `CalendarResult` / `SolarTermDef` / `SOLAR_TERMS` / `DEFAULT_TIMEZONE` |

処理の流れ:

1. `julian.ts` … `Intl.DateTimeFormat` のオフセットで壁時計 → UTC（DST 境界は 2 パス補正）。
   `AstroTime.ut + 2451545.0` で Julian Day、`(AstroTime.tt − AstroTime.ut) × 86400` で ΔT。
2. `solarTerm.ts` … 太陽黄経、それが属する 15° 刻みの節気、その節入り瞬間（二分法で逆算）。
3. `eto.ts` … 立春境界で年干支、太陽黄経（節月序数）で月干支、JDN で日干支、五鼠遁で時干支。

# 干支計算の確定仕様（現行実装＝正）

以下は docs 02/03/05 に元々明記が無かったが、実装で採用済みの正式仕様。

## 年干支

- その年（グレゴリオ暦年）の**立春（太陽黄経 315°）の瞬間**を二分法で求め、
  対象時刻がそれ以降なら当年、手前なら前年を「暦年」とする。
- `1984 = 甲子` を基準に `mod(暦年 − 1984, 60)` で干支インデックスを決定。

## 月干支

- 太陽黄経から節月序数を求める: `floor(mod(太陽黄経 − 315, 360) / 30)`
  （0＝寅月〔立春〜〕、1＝卯月〔啓蟄〜〕… 11＝丑月〔小寒〜〕）。
- 月支 = 寅から数えて節月序数ぶん進めた地支。
- 月干 = 五虎遁: `mod((年干インデックス % 5) × 2 + 2 + 節月序数, 10)`。

## 日干支

- **日の切替は子初 23:00**。対象の現地時 `hour ≥ 23` なら翌日の暦日として扱う。
- その暦日の正午（UTC）の Julian Day を四捨五入して JDN とする。
- `1984-02-02 = 丙寅` に合わせた補正値 `+49` を用い、`mod(JDN + 49, 60)` で干支インデックスを決定。

## 時干支

- 時支インデックス = `floor((hour + 1) / 2) mod 12`（23時・0時＝子、以降 2 時間ごと）。
- 時干 = 五鼠遁: `mod((日干インデックス % 5) × 2 + 時支インデックス, 10)`。

# 既存資産との関係

## astro.ts（`src/lib/astro.ts`）

役割: 天文計算ライブラリ（ユリウス日・太陽位置・月位置・天体黄経・ASC 計算など。内部で `astronomy-engine` を使用）。

**設計意図**: 既存の天文計算資産を共通暦エンジンの中核として利用する。

**現行の事実**:
- 太陽黄経は astro.ts の `sunLonDeg()` を利用（節入り時刻の逆算・`sunLongitude` の両方）。
- **Julian Day と ΔT は `astronomy-engine`（`Astronomy.MakeTime`）を `julian.ts` / `eto.ts` から直接呼んで取得**しており、astro.ts 内の `julianDayUTC()` は使っていない。
- astro.ts 自体は変更していない。

## eto.ts（`src/lib/eto.ts`）

役割: 既存の干支計算ライブラリ（固定日付で節入りを判定する簡易版）。

**現行の事実**:
- 既存 `src/lib/eto.ts` は**変更していない**。七政四餘 `page.tsx` は引き続きこれを使う。
- 共通暦エンジンの干支計算は `src/lib/calendar/eto.ts` として**別途新規実装**した
  （節入り時刻を天文計算で境界に用いる）。
- 干支名テーブル `STEMS` / `BRANCHES` と型 `Stem` / `Branch` のみ既存 `src/lib/eto.ts` から再利用。

## branch_from_lon.ts

七政四餘専用。共通化しない。維持。

## geom.ts

描画ライブラリ。共通暦エンジンへ組み込まない。
