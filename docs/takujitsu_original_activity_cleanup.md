- 「狩猟」→「畋獵」を統合すると、季節限定のはずの畋獵が常時宜になってしまう

- 原典が意図的に「常時の一般語」と「季節限定の精確な classical 語」を書き分けている可能性が
  高く、「意味が近いだけの古典用事同士は統合しない」の対象と判断。

→ **「狩猟」「魚取」「魚釣」「魚釣り」は統合せず、178件の中に独立したidのまま残っている。**

## 1. 狩猟・魚釣り問題の構造調査（結論：統合しない。ただし設計上の問題を報告）

`docs/source/12建除.pdf`の十二直（十二建除）原文を直接確認した。

### 12建除.pdf 原文（p.7-8、該当箇所そのまま）

```
⑥執日(しゅうじつ)
執着する日なので魚釣・漁業、狩猟に吉

⑪開日(かいじつ)
門の設置、水口の設置に良い日である。風水の造作に良い。放水に吉。埋葬、
魚釣・漁業・狩猟は凶
```

12建除.pdfの執日・開日の説明文は、**「魚釣・漁業・狩猟」を一括りの日本語要約として
記載しているだけで、「畋獵」「取魚」という語も、季節条件（霜降後立春前／雨水後立夏前）も
一切登場しない**。

一方、`docs/source/神殺象意.pdf`（原典・classical）の執日は、
`tests/fixtures/shinsatsu_shogi_source.py`の転記（原本画像で確認済み）で：

```
"執": {"favorable": ["捕捉"], "unfavorable": [],
       "note": "季節条件: 霜降後立春前は畋獵、雨水後立夏前は取魚も宜"}
```

つまり原典（神殺象意.pdf）は「捕捉は常時宜、畋獵は霜降後立春前のみ宜、取魚は雨水後立夏前
のみ宜」と**季節条件つきで正確に書き分けている**。

### 結論

現行の`activityProfiles.ts`は、執・危・収の`favorableActivityIds`（常時宜）に
「魚釣り・漁業・狩猟・捕捉」を、`seasonalRules`（季節限定宜）に「畋獵・取魚」を
**別ActivityDefinitionとして並存**させている。しかし12建除.pdfの原文を確認した結果、
**「魚釣り・漁業・狩猟」が季節条件なしの独立した原典用事として存在するという根拠は無い**。
これは12建除.pdf（日本語教材）が神殺象意.pdf（原典）の季節限定ルールを**簡略化して**
「魚釣・漁業、狩猟に吉」とだけ書いたために生じた、**教材側の要約の粗さ**である。

したがって、本来あるべき設計は「畋獵・取魚・捕捉のみがcanonicalで、常時宜／季節限定宜の
区別はActivityProfileの構造（favorableActivityIds vs seasonalRules）だけで正しく表現する」
形のはずである。**しかし、これを今回そのまま実施する（狩猟→畋獵、魚釣り→取魚を統合する）と、
畋獵・取魚が執・危・収のfavorableActivityIds（常時宜）にも入ってしまい、季節限定という
原典の制約が壊れる**ことを前回の差分テストで確認済みである。

**この矛盾はActivityDefinitionの統合だけでは解決できず、activityProfiles.ts側の
ロジック（執・危・収のfavorableActivityIdsから「魚釣り・漁業・狩猟」を外し、必要なら
神殺象意.pdf原典の季節条件に置き換える）を変更しないと正しく直せない。** 今回はロジック
変更をしない指示のため、**「狩猟」「魚取」「魚釣」「魚釣り」「漁業」は統合せず保留する**。

### 提案（実装はしない。設計案の報告のみ）

将来ロジック変更が許可される場合の対応案：

1. 執・危・収の`favorableActivityIds`から「魚釣り」「漁業」「狩猟」を削除する
   （神殺象意.pdf原文に常時宜の根拠が無いため）。
2. 「捕捉」は常時宜のまま維持する（神殺象意.pdfが明記）。
3. 「畋獵」「取魚」は`seasonalRules`の季節限定宜のみとし、canonical
   ActivityDefinitionを畋獵・取魚・捕捉に一本化する。
4. 「狩猟」「魚取」「魚釣」「魚釣り」「漁業」は削除するか、`modernName`／表示用の
   別名として畋獵・取魚・捕捉へ吸収する。
5. 「開」の忌リストに残る「魚釣り」「漁業」「狩猟」「畋獵」「取魚」の重複（現在5語すべてが
   併記されている）も同様に、畋獵・取魚だけに整理できる。

この設計変更自体は次工程（ユーザー判断）に委ね、**今回は現状維持**とした。
