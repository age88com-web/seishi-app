## 1. 骨格（構造）の生成方法

`dayGanzhi`（60干支）と`hourBranch`（12支）の全組み合わせ720件を機械生成し、
`hourGanzhi`は日干から五鼠遁の標準式で計算した（`docs/takujitsu_jika_analysis.md`
1.3節で確認済みの式。今回は**全10ページ分、各ページの最初の局の時辰見出しを
実際の原本画像と突き合わせ、五鼠遁の計算結果と完全一致することを確認した**
（3.1節参照）。

```
60日干支 = 10干 × 6支（各干は自分と同じ陰陽の6支とだけ組む）
12時辰 = 子丑寅卯辰巳午未申酉戌亥
720 = 60 × 12
```

生成結果を検証した結果、**総レコード数720、欠落0、重複0、各日干支に
時辰がちょうど12件**であることを確認した（`tests/fixtures/jika_720_skeleton.json`）。

## 2. 内容（神殺名）の転記状況

各マスの内容（`kichijin[]`／`kyojin[]`／`rawText`）は、原本画像を最大9〜10倍に
拡大して1マスずつ目視で読み取る必要があり、720マス全件を今回のラウンドで
転記することはできなかった。**今回は10ページ全てから合計50マスを選び、
最終ページの神殺プロフィール（`docs/takujitsu_jika_shinsatsu_profiles.md`）を
辞書として照合しながら転記した**（3章）。

読み取り方式：各マスは「煞＋方位（北／南／東／西）」に続けて、2〜3個の
2文字神殺名が「上段文字＋下段文字」の組み合わせで縦2段に印字されている
（例：上段「天／右／三」、下段「刑／弼／合」→「天刑」「右弼」「三合」の3神）。
この読み方は複数マスで既知語彙（三合・青龍・司命など）と整合することを
確認したうえで採用した（推測ではなく、複数マスでの再現性により方式を確定）。

50マスのうち32マスは、抽出した神殺名がすべて`docs/takujitsu_jika_shinsatsu_profiles.md`
の凡例に**完全一致**した。残り18マスには、凡例側で分離・確認できていなかった
語（進貴・日祿・交貫・比肩・財局・祿貴・狗食・進祿、および「勿用」という
神殺名ではなく指示文と思われる語）が含まれており、これらは`unresolved[]`に
記録し、canonicalな神殺名として確定していない。

**2026-09-12追記（`docs/takujitsu_jika_shinsatsu_names_audit.md`で名称マスター監査を実施、
ユーザーが原本を直接確認して複数回訂正）**：「交貫」は誤読で正しくは**「交貴」**
（甲午／未・乙未／申の両出現とも訂正済み。既存の別神殺への統合はせず独立語として
保持）。「財局」は誤読セル（戊午／辰。正しくは「喜神・武曲・天兵」で、財局・
路空・三合はいずれもこのセルには存在しない）のみを根拠としていたため、**神殺
名称候補から除外**する。「祿貴」は本監査で一時「祿貫」の誤読と判定していたが、
これも誤りでユーザー原本確認により**「祿貴」に復元**した（吉神析義列5＝羅紋・
祿貴・交馳の3語で確定）。「狗食」は独立神殺ではなく**天狗凶時＋下食凶時の
複合略記**、「進貴」は**羅紋の略記**、「進祿」は**祿貴の略記**であることを
ユーザーが原典P7で確認した（正式神殺と720表中の略記表現は区別し、原表転記の
表記自体は書き換えていない）。「日祿」（その日の祿）・「比肩」（日干と同じ）
はユーザー確認により**正式な時家用語として確定**した（吉凶分類・発生公式の
実装は今回行わない）。これにより720表側で今回ユーザー確認が必要だった名称は
**すべて解消**した。その後、凡例側（吉神析義下段10列を含む）もユーザー原本
確認により全て確定し、**時家神殺名称マスターは完全確定（YES）**となった。
詳細は`docs/takujitsu_jika_shinsatsu_names_audit.md`13章を参照。

残る670マスは、骨格（`dayGanzhi`／`hourBranch`／`hourGanzhi`）のみを生成し、
`kichijin`／`kyojin`は空配列、`unresolved`に「未転記（本ラウンドでは骨格のみ
生成、内容未読）」と明記した。**これは判読不能という意味ではなく、単に
今回のラウンドで転記に着手していないという意味である**（誤読の記録と混同
しないよう明確に区別している）。
