## 1. 年柱

1. **入力**: 生年月日時（節入り判定に使う時刻を含む）
2. **計算規則**:
   - 年の境は**立春**。立春より前に生まれた場合は前年の干支とする（p20）。
   - 干支そのものは万年暦から読む（p20「常に万年暦を使う」）。
3. **出力**: 年干・年支
4. **例外**:
   - 1月1日〜立春前の生まれ → 前年干支（例: 長嶋一茂 1966/1/26 → 乙巳年、雛形あきこ 1978/1/27 → 丁巳年、宇多田ヒカル 1983/1/19 → 壬戌年）
5. **根拠**: p20（命式の出し方）、p25（万年暦ページ例：2020年、立春 2/4 18:03）
6. **未確定事項**:
   - 立春当日の境界を**分単位の節入り時刻**で判定するか、日単位で判定するか（p20 は「だいたい2月4日」、p25 の万年暦には時刻付き節入りが載る）。
   - 節入り時刻と比較する出生時刻が、時計時刻か時差・均時差補正後の時刻か。

## 2. 月柱

1. **入力**: 生年月日時
2. **計算規則**:
   - 月の境は**二十四節気の節**（万年暦で印が付いている日）。境より前は前月の干支（p20）。
   - 干支は万年暦から読む。
   - 月支と節の対応: p25 の万年暦（立春=寅月、啓蟄=卯月、清明=辰月、立夏=巳月、芒種=午月、小暑=未月…）。
3. **出力**: 月干・月支
4. **例外**: 節入り日の生まれ（下記未確定）
5. **根拠**: p20、p25
6. **未確定事項**:
   - 月干を**計算で**求める規則は講座にない（万年暦参照のみ）。p113 の「命宮の天干」表は年干×月支→干の形をしているが、**命宮用として提示されており、月柱の算出規則としては明示されていない**。
   - 節入り当日の判定精度（日単位か時刻単位か）。

## 3. 日柱

1. **入力**: 生年月日時
2. **計算規則**:
   - 日干支は万年暦から読む（p20, p25）。
   - **日の境界（ユーザー確認済み確定仕様 D3）**: 23:00で日が変わる（早夜子）。
     - 22:59まで＝当日の日干支
     - 23:00以降＝**翌日**の日干支
     - 23時台の時柱は、切り替え後（翌日）の日干で時干を求める（§4）。
3. **出力**: 日干・日支（日干＝日主・命主、p57）
4. **例外**: 23:00〜23:59 は翌日扱い（上記）
5. **根拠**: 講座本文に日の境界の明記はない（p20, p24, p25）。D3 はユーザー決定。
6. **資料内不整合（D4）**:
   - p17 タイタニック号「1912年4月14日午後11:40」の命式は **日柱 庚申・時柱 戊子**。p24 の表で庚日の子刻は丙子であり、戊子は丙・辛日（＝翌日の辛酉日）の子刻にあたる。つまりこのスライドは「日柱は当日のまま、時干だけ翌日の日干で出す」扱いになっている。
   - D3（23:00で日干支も翌日に切り替える）ではこの例は日柱が辛酉になるため、**確定仕様と一致しない**。資料内不整合として `needs_review: true`、自動テストの対象外とする。
7. **23:00 の判定に使う時刻**: D7・D8 の補正後時刻（地方真太陽時）で判定する（ユーザー確認済み確定仕様）。

## 4. 時柱

1. **入力**: 出生時刻、日干、（出生地）
2. **計算規則**:
   - 時干支は万年暦、または**時干支一覧表**（p24）から出す（p21）。
   - 出生時刻には次の補正を「考慮する」（p21）:
     - サマータイム（日本では1948〜1951年に実施）: 1時間戻す
     - 地域時差: 明石標準時（東経135°）との差（p22 の表）
     - 均時差（p23 の表）
   - **補正の手順と、補正後時刻の使い方は D7（国内）・D8（海外）で確定（§4.4）**。時支と23:00の日替わりは補正後時刻（地方真太陽時）で決める。
   - 時干は、その時刻が属する日の日干で p24 の表を引く。23:00〜23:59 は翌日の日干を使う（D3。§3 で日干支自体も翌日に切り替わるので、結果として「その命式の日干」で引くことになる）。
3. **出力**: 時干・時支
4. **例外**:
   - 時刻不明 → 時柱は空欄（p85 千昌夫、p110 陣内智則は時柱なしで表記）
   - 時刻ちょうど（例 13:00）は後の時刻帯に入る: p20 の例 2010/7/20 13:00 → 未刻（乙未）。
5. **根拠**: p21, p22, p23, p24, p20
6. **未確定事項**:
   - 補正後時刻を年柱・月柱の境界（立春・節入り）の判定にも使うかどうか（D7・D8 は時支と日替わりのみを定める。U6）。
   - 講座の例題が時刻補正を反映しているかどうかは明示されていない。fixture 照合（§12）で分かった事実:
     - 出生地が書かれている国内の例題は、すべて D7 の補正後時刻でも時計時刻でも同じ時支になり、講座の値と一致する（イチローを除く）。
     - イチロー（1973/10/22 8:43 愛知県）: p96 の壬辰は時計時刻の値。p29・p63 の癸巳は「8:43＋地域時差（名古屋 +7分）＋均時差（10/22 +15分）＝9:05 → 巳刻」とすると一致する。講座内で補正の有無が混在している可能性がある（資料内不整合として扱い、判断はしない）。
   - 23時台は D3 により翌日の日干で時干を出す（§3）。

### 4.4 時刻補正（ユーザー確認済み確定仕様 D7・D8・D9）

命式計算用時刻＝**出生地の地方真太陽時**。使うのは**時支と23:00の日替わりだけ**。年柱・月柱の節入り判定には使わない（D10、§5）。

| 手順 | 日本国内（D7） | 海外出生（D8） |
|---|---|---|
| 1. 入力 | 日本標準時で記録された出生時刻 | 出生地で記録された現地時刻 |
| 2. サマータイム | 講座 p21：日本では1948〜1951年に実施。該当する日時なら考慮して標準時に戻す | 実施中なら考慮して当時の現地標準時に戻す |
| 3. 基準 | 日本標準子午線（東経135°） | 当時の現地標準時の標準子午線 |
| 4. 地域時差 | p22 の表の値。表にない出生地は経度から計算：（経度−135）×4分 | （出生地の経度−標準子午線）×4分 |
| 5. 均時差 | p23 の表の値を加える（D9） | 同左（D9） |
| 6. 結果 | 地方真太陽時で時支を決め、23:00の日替わりを判定 | 同左 |

符号: p22・p23 の値をそのまま足す（東はプラス、西はマイナス。均時差は2月 −14、11月 +16 など）。
計算例（イチロー、p29・p63）: 8:43 ＋ 7（名古屋） ＋ 15（10/22 の均時差）＝ 9:05 → 巳刻。

**外部基礎データ（講座の判断規則ではない）**: 海外の標準時・サマータイムの履歴、p22 にない地点の経度。

#### 4.4.1 p22 の表と経度計算の照合（D7 の確認）

各都市の市役所付近の経度（**一般知識による概略値・外部基礎データ。公式の座標で置き換えが必要**）で（経度−135）×4 を計算し、p22 の59地点と比べた。

| 丸め方 | 一致 | 不一致 |
|---|---|---|
| 四捨五入 | 49 | 10 |
| 切り捨て（0方向） | 33 | 26 |

- p22 の注記は「秒単位切り捨て」だが、四捨五入のほうがよく合う。表の元にした座標が分からないので、どちらの規則かは断定できない。
- 四捨五入で合わない10地点のうち8地点は、計算値が .5 前後（釧路 37.52、釜石 27.54、宇都宮 19.53、静岡 13.53、大分 −13.55 など）か、差が1分以内（旭川 29.46→表30、盛岡 24.61→表24、名古屋 7.63→表7）で、座標の取り方の違いで説明できる範囲。
- **大きく外れるのは2地点**:
  - **金沢**: 表は 15分、計算は約 6.5分（東経136.63°）。差は約8.5分。
  - **横浜**: 表は 17分、計算は約 18.6分（東経139.64°）。差は約1.6分。
- **結論**: 経度計算は p22 の表と「ほぼ一致（±1分）」だが、**完全には一致しない**。D7 の手順どおり、表にある地名は表の値を使い、表にない地名だけ経度で計算する。
- **金沢（ユーザー確認済み確定仕様 D15。U24 は解除）**:
  - 講座記載値: **15分**（p22 の原文。資料の記録として残す）
  - 経度計算: **約6.5分**（東経約136.63°）
  - **講座記載値15分は誤植と判断し、計算には採用しない**（福井が5分であることや地理的な経度関係から判断）。
  - 金沢は表にない地点と同じく、出生地の経度から地域時差を計算する。金沢だけの特例は作らない。
  - 金沢を理由に fixture を needs_review にしない。
  - 経緯: D14 で「特例を作らず要確認」としたあと、D15 で誤植と判断して確定。

#### 4.4.3 海外出生の法定時刻（ユーザー確認済み確定仕様 D29）

外部基礎データ: **IANA Time Zone Database**。占術規則ではなく、出生地の法定時刻を確定するためのデータ。出生地には可能な限り IANA timeZone ID（`Europe/London`・`America/Los_Angeles`・`Australia/Sydney` など）を持たせる。

1. 出生地の現地法定時刻を受け取る
2. IANA の履歴から、その日時の標準時とサマータイム（DST）の適用状況を確認する
3. DST 適用中なら標準時に戻す
4. 標準子午線と出生地の経度の差から地域時差を求める
5. p23 の均時差を加える
6. 地方真太陽時を求める

- 方針: 追加パッケージは入れず、既存の `Intl.DateTimeFormat` と IANA timeZone ID で実装する。
- 標準時とDSTの分離（実装時にユーザー決定）: Asia/Tokyo は日本標準時 +540分（東経135°）固定。海外は当時の標準時オフセット（`standardOffsetMinutes`）を入力で必ず明示し、自動推定しない。サマータイム分＝IANA の法定オフセット−標準時オフセット。理由: `Intl` のタイムゾーン名では東京1949年夏・米国戦時時間などのサマータイムを判別できないため。
- 既存の仕組み: 共通暦エンジン（`src/lib/calendar/julian.ts`・`lunisolar.ts`）と奇門遁甲（`src/lib/qimen/dingju.ts`）は、`Intl.DateTimeFormat` の `timeZone` で IANA ID を扱っている（追加パッケージなし）。現地時刻と UTC の相互変換と、合計オフセットの取得はできる。ただし、合計オフセットのうち標準時とDSTがそれぞれいくつかを直接返す機能はない（手順2・3に必要）。

## 5. 節入り

1. **入力**: 出生の瞬間（出生地の標準時。地方真太陽時の補正はしない）
2. **計算規則（ユーザー確認済み確定仕様 D10）**:
   - 節入りの算出は、**擇日エンジンと共通の既存ロジックを唯一の基準**とする。四柱推命専用のロジックは作らない。
   - 年柱: 立春の瞬間より前なら前年（p20）。
   - 月柱: 各節の節入りの瞬間を境に切り替える（p20）。
   - 立運: 順行は次の節、逆行は前の節までの日数（p28、§6）。
   - 節入りの瞬間と出生の瞬間を同じ標準時で比べる。節入り時刻に経度補正や均時差を加えない。
3. **出力**: 年干支・月干支、前後の節の名前と節入り日時
4. **例外**: なし（講座記載なし）
5. **根拠**: p20、p25（例: 2020年 立春 2/4 18:03、啓蟄 3/5 11:57、清明 4/4 16:38、立夏 5/5 09:51、芒種 6/5 13:58、小暑 7/7 00:14。中気として 雨水・春分・穀雨・小満・夏至・大暑 も載る）

## 6. 大運

1. **入力**: 性別、年干の陰陽、月柱、生年月日時、前後の節入り日
2. **計算規則**（p28, p29）:
   - **順逆**:
     - 年干が陽干: 男性＝順行（甲子→乙丑→丙寅…）、女性＝逆行（甲子→癸亥→壬戌…）
     - 年干が陰干: 男性＝逆行、女性＝順行
   - **大運干支**: 月柱から六十甲子を順行または逆行で1つずつ進める。第1大運は月柱の次（または前）の干支になる（全例で確認）。
   - **立運（立命）**: 生まれた日から月の境（節）の前日までの日数を数えて3で割り、四捨五入する。逆行の場合は前の節まで遡って数える。「一ヶ月を10年と考えると3日が1年となるため」。
   - **大運の年齢（ユーザー確認済み確定仕様 D23）**: **数え年**で表示する。立運年齢も数え年で、その年齢から第1大運が始まり、以後10年ごとに切り替える。

| 立運3歳の例 | 大運 |
|---|---|
| 3〜12歳 | 第1大運 |
| 13〜22歳 | 第2大運 |

本文から読める数え方:

**例題での比較**（節入り日は共通エンジン、国内は日本標準時、海外は D17 の現地標準時。出生地不明のジョブズを除く24例）

|---|---|---|---|

| D 実日数（出生時刻から節入り時刻までの時間÷24） | **19** | 16 | 3 |

| B 日付の差＋1（両端を含む） | 12 | 10 | 2 |

- A と D は、講座の全例で同じ結果になり、例題からは区別できない（差が出るのは、日付の差と実日数の差で四捨五入の結果が変わる境界の例だけで、講座にはない）。

## 12. 例題 fixture 候補一覧

正本の fixture 候補は **`docs/shichusuimei-fixtures-candidate.json`**。本節はその要約。

### 12.1 共通ルール

- どの fixture も `source_pages`（出典ページ）・`input`（入力）・`expected`（期待値＝講座の表記）・`needs_review` を持つ。
- `needs_review: false` のものだけが、将来の自動テストの正解候補。`true` のものは自動テストに使わない。
- `review_code`:
  - `SOURCE_CONFLICT`＝資料内不整合（D4 の人物、タイタニック号、p28 の規則と合わない立運など）
  - `SPEC_DEPENDENT`＝未確定の仕様（U6 の節入りの扱いなど）によって期待値が決まらない
  - `INPUT_INSUFFICIENT`＝講座に出生地などの記載がなく、D7・D8 の補正後時刻が決まらない（講座の値と矛盾しているわけではない）
- D4 の人物（イチロー・山口もえ・マイケル・ジャクソン・荒川静香・小倉優子）は、食い違いのない項目も含め、その人物の fixture をすべて `needs_review: true` にしている。
- 柱の並びは講座の表記順 **時・日・月・年**。時刻不明は `null`。大運 `luck` は若い年齢から順。
- 性別は講座に明記がない（実在人物の性別を入れている。講座の大運の順逆とも全例一致）。
- `reference` は照合のための参考値（CalendarEngine の計算値、節入り日時など）。**正解ではない**。

### 12.2 安全性の判定方法

講座内の情報だけで次を照合した（照合スクリプトはリポジトリ外、コード本体は未作成）。
