# 六壬 Phase 5J：不足 FACT の横断監査と実装優先順位

Phase 5A〜5I で実装した11の DOMAIN（仕事・試験・家宅・行人・出行・婚姻・疾病・求財・売買・訴訟・失物・妊娠・出産）を横断して、
保留されている古典判断と、それを解放するのに必要な FACT を調べた。今回は調査と設計だけで、コード・FACT・DOMAIN 規則・UI は変更していない。

- 調査したコード: `src/lib/liuren/interpretation/` の DOMAIN 10ファイル（careerDomain・houseDomain・travelerDomain・travelDomain・marriageDomain・illnessDomain・wealthDomain・litigationDomain・lostItemDomain・pregnancyDomain）、`domainBoardInput.ts`・`roles.ts`、共通 FACT（markers・natalYear・taiSui・personContext・voidStructure・states・patterns・yinSpirit・heavenlyGeneral*・identityLink*・movementFacts）、対応する `tests/liuren_interpretation_*_domain.manual.ts`
- 調査した資料: 『大六壬指南』（総論〜兵斗章）、『御定六壬直指』（各占・毕法賦）、『六壬心鏡』巻一〜巻八、『六壬大全』卷九・卷十 毕法賦・鬼墓課・逆十二格、『六壬断案』『六壬断案２』、『六壬神課講座』
- 照合: 起例の候補と原典の例の照合は Python の調査用スクリプトで行った（リポジトリには入れていない。結果は §4）

区分の記号（§2 の表で使う）:

| 記号 | 意味 |
|---|---|
| **A** | FACT を追加すれば解放できる（算法が原典で確定し、規則の見る位置も原文で決まる） |
| **B** | FACT の追加に加えて、新しい入力（人物の性別・数え年・病日・配偶者など）が要る |
| **E** | 既存の FACT だけで解放できる（FACT 不足が保留の理由ではなかった） |
| **X** | FACT を追加しても原典の解釈が確定しない（見る位置・語の定義・原典どうしの食い違い・資料不足） |
| **O** | 方針で出さない（応期・日時、医療行為、人物評価・犯人推定、方角、刑罰） |
