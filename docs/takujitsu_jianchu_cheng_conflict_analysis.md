## 7. 資料優先順位（4案の比較）

前提：本エンジンの十二建除 ActivityProfile は
**`sourceType:"jianchu"` の LIST 型**。既存の執・危・収の3直は、
「季節条件完成フェーズ」（2026-09-09）で**12建除.pdf 由来の用事と
神殺象意.pdf 由来の用事を1つの `favorableActivityIds` に併記**している
（実測、§7.1）。

### 7.1 執・危・収の前例（重要）

| 直 | favorableActivityIds（現行） | 12建除.pdf 由来 | 神殺象意.pdf 由来 |
|---|---|---|---|
| 執 | 魚釣り・漁業・狩猟・**捕捉** | 魚釣り・漁業・狩猟 | 捕捉（＋季節宜） |
| 危 | ベッドの買い替え・設置・移動・子作り・**安床** | 前4語（＋忌 乗船） | 安床（＋季節宜） |
| 収 | 埋葬・出かける・結婚式・**進人口・納財・捕捉・納畜** | 埋葬・出かける・結婚式 | 進人口・納財・捕捉・納畜（＋季節宜＋月恩四相時徳クロス条件） |

**3直とも「削除せず併記（union）」で統一されている。**

### 7.2 4案

| 案 | 内容 | 根拠 |
|---|---|---|
| **A** | 成 = 入學・移徙・築堤防・開市（神殺象意.pdf 優先、婚姻系を削除） | 神殺象意.pdf は日家神殺の専用辞典で用事の粒度が細かい。「入学・移転・堤防・開店」は「成就」の具体例として一貫。**ただし12建除.pdf という別の一次資料が明記した「婚姻・結婚・結納」を削除する根拠が原典に無い**（12建除.pdf が誤りだと言える材料が無い） |
| **B** | 成 = 婚姻・結婚・結納（現行維持、神殺象意.pdf を反映しない） | 12建除.pdf は `jianchu.ts` の唯一の仕様根拠。既存データの凍結を尊重。**ただし神殺象意.pdf という一次資料の確定記述を無視することになり、執・危・収の前例（神殺象意.pdf を併記）と不整合** |
| **C** | 成 = 婚姻・結婚・結納・入學・移徙・築堤防・開市（7語 union） | **執・危・収と完全に同じ扱い**。どちらの一次資料の記述も削除しない。「成＝成就＝万事の達成」という両資料共通のテーマとも整合。両者は矛盾ではなく粒度・観点の差（§8）。追加の特別ルール不要（§9・§10） |
| **D** | 出典別 profile として分離保持（12建除由来 / 神殺象意由来を別 source で持つ） | 判定ロジック上、`favorableActivityIds` は1配列で source は `{jianchu, 成}` 1つ。出典を分けるには `ActivitySource.note` に「12建除.pdf由来」「神殺象意.pdf由来」を分けて持つ設計が必要。**執・危・収では分けていない（併記で1 source）。成だけ分ける必要性は無い** |

### 7.3 本当に CONFLICT か（§17〜19）

**厳密には「CONFLICT」ではなく「粒度・観点の差」。**

- 12建除.pdf：「成＝全てに吉、特に婚礼」。十二直の一般解説として
  「成就」の代表例に婚礼を挙げている。
- 神殺象意.pdf：「成＝入學・移徙・築堤防・開市」。日家神殺辞典として
  「成就」の具体的な用事を4つ列挙。加えて天喜・天醫の日。
- **両者に直接の矛盾（同じ用事を一方が宜、他方が忌）は無い。**
  重複が無いのは、粒度と代表例の選び方が違うため。
- **両立可能**（§19）：7語すべてを宜としても原典間の衝突は生じない。

前フェーズ（`takujitsu_except_resolution_final.md` 3章）が「CONFLICT・
重複が無い・要検討」としたのは、**用事リストとして1件も重ならない**という
事実の記述であって、内容が矛盾しているという意味ではない。

### 7.4 推奨案：**C案（7語 union、LIST型）**

```
{ sourceType:"jianchu", sourceName:"成",
  favorableActivityIds:["婚姻","結婚","結納","入学","移徒","築堤防","開市"],
  unfavorableActivityIds:[] }
```

**推奨理由：**

1. **執・危・収の前例と完全に一致**。3直で確立した「12建除.pdf 由来＋
   神殺象意.pdf 由来を1配列に併記」を成にも適用するだけで、十二建除
   4直（執・危・収・成）の扱いが統一される。
2. **どちらの一次資料の確定記述も削除しない**（「既存の一次資料が明記した
   内容を削除してよいかはユーザー判断」という六黄道フェーズの方針とも
   整合。今回は削除せず併記＝ユーザー判断を要さない安全側）。
3. **ALL型にしない**：12建除.pdf の「全てに吉」は現代日本語の要約であり、
   神殺象意.pdf が ALL型に使う「諸事皆宜」の定型句ではない。
   `takujitsu_720_generation_analysis.md` も「成日＝全てに吉」を全256語
   positive 化する根拠にしていない。LIST型（7語）に留める。
4. **一致率は A/B/C いずれでも変わらない**（§8）ので、数値を理由に
   A/B を選ぶ動機が無い。原典の網羅性を最大化する C が素直。
5. **追加の特別ルール不要**（§9・§10）。成は通常の LIST 型 jianchu positive
   source になるだけ。

**残る不確定（ユーザー判断が要る場合）：**

- C案は「執・危・収の前例に倣う」という**方法論的整合**を最優先している。
  もし「十二建除は 12建除.pdf のみを唯一の根拠とし、神殺象意.pdf の
  十二直記述は一切反映しない」という方針を採るなら B案（ただし執・危・収も
  巻き戻す必要が生じ、既に実装済みのため非推奨）。
- 移徙の id は既存 `移徒` を流用（新 id を作らない）。
