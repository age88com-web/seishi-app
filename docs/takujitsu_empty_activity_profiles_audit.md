### 5.4 歸忌 の詳細（IMPLEMENTABLE）

- **神殺象意.pdf に明示的な忌「移徙」がある**。`shinsatsu_shogi_source.py`
  （前フェーズの手動転記、「推測での追加なし」と明記）に
  `"歸忌": {"unfavorable": ["移徙"], "note": "徳合/赦/願併: 猶忌。俗忌: 出行,嫁娶"}`
  として転記済み。本フェーズで p.4（原本 一七／一八）の
  〔往亡〕〔歸忌〕併記ヘッダー付近を6倍で確認し、「移徙」の字が同区画に
  存在することを目視確認した（隣接列の近接によりヘッダーとの厳密な
  対応は scan 品質上100%断定はできないが、転記データと整合）。
- **空になっている原因は「原典に記載が無い」ではなく、
  「移徙 → ActivityDefinition id のマッピングが SAFE_ADD フェーズで
  『未確認』として除外された」**：
  - ActivityDefinition には `移徙` id が無く、`移徒`（「転入居日、引越し」、
    用事便覧No.42）だけがある。
  - `activityProfiles.ts` ヘッダーコメント（48行目）が明記：
    「移徙（既存id『移徒』との類似語ペア、未確認）のような類似語は
    統合していない（保留のまま、SAFE_ADDから除外）」。
  - 同じ転記データで 往亡 は8語のうち7語が profile に入っているが
    **移徙（8語目）だけが同じ理由で落ちている**（往亡 profile ＝
    転記データ − 移徙）。歸忌 は忌が移徙1語だけなので、除外の結果
    profile が空になった。
- **移徙 ＝ 移徒**：移徙は「移転・引越し」の古典表記、移徒（辞書id）は
  「転入居日、引越し」。意味は同一。かつ **成日 C案フェーズ（2026-09-10）で
  神殺象意.pdf の「移徙」を id `移徒` にマッピングする対応が既に確立済み**。
  同じ対応を歸忌にも適用すれば、`unfavorableActivityIds: ["移徒"]` として
  実装できる。
- **720影響**（`gk.ts` 実測）：engine の歸忌 occurrence は60/720日。
  そのうち擇日象意.pdf が「移徒」を宜としている日は0（歸忌が移徙を忌む
  ので当然）。→ 追加しても MATCH は減らない。
