## 1. 比較指標の完全な相違点

前回85.52%（`docs/takujitsu_shinsatsu_shogi_audit.md`10〜11章）と
今回56.3%（`docs/takujitsu_except_resolution_final.md`本番反映結果）は
**同じ定義の一致率ではなかった**。相違点は以下の7点：

| 項目 | 前回（85.52%） | 今回（56.3%） |
|---|---|---|
| 比較対象行数 | 718（sourceGap 2行除く） | 718（同左） |
| ActivityDefinitionの対象範囲 | favorable_expanded＝**擇日象意.pdf自身の34語彙**へ限定投影 | ActivityDefinition**全256語**（当時242語） |
| ALL型の展開方法 | 34語彙のうち例外(畋獵・取魚)を除いた32語のみ | 256語全体のうち例外を除いた254語 |
| EXCEPT型の扱い | 未実装（凶神を一切考慮しない） | negativeMode:"all_except"で全256語からexceptionを除く忌スイープ |
| resolution適用 | 未適用 | 適用（凶神のcancel/reduce/aggravate） |
| 生成側フィルタ | raw union（宜候補の単純合算。忌との相殺なし） | **verdict==="good"**（宜のみ・忌が1件でもあれば除外） |
| 十二建除・二十八宿 | 含めない | 含める（59.9%側） |
| occurrence源 | 擇日実例.pdfのground-truthトークンをそのまま使用 | `calculateShinsatsu()`で実日付から再計算 |
| 一致率の計算式 | MATCH / (MATCH + SHOGI_ONLY) | 同左（式自体は同じ） |

一致率の**計算式そのもの**（MATCH/(MATCH+SHOGI_ONLY)、いわゆる再現率）は
同一だったが、**MATCH・SHOGI_ONLYを生む「生成宜集合」の作り方が7点とも
異なっていた**。したがって85.52%→56.3%の低下を単純な「精度が落ちた」
「バグが入った」と解釈することはできない。

## 5. ALL型の実装確認（今回の核心）

**確認結果：現在の実装は、ActivityDefinition全256語からexceptionを除く
という「文字通りの諸事皆宜」になっている**（`evaluateActivities.ts`の
`resolveFavorableIds()`が`ACTIVITY_BY_ID`全件を展開）。

一方、擇日象意.pdf自身が扱う固有語彙は**34語**（`docs/takujitsu_activity_design.md`
3章で確認済みの50語のうち、720行のexpectedCombinedとして実際に出現する
のはこの34語）。したがって、**242〜256語全体を生成した結果を34語の
答えと比較して、生成側の残り220語超を無条件でLOGIC_ONLYに数えている**
のが実態である。

これは検証方法（比較の射影範囲）の問題であり、**ActivityProfile・
evaluateActivities側の実装バグではない**。実際、E段階を34語彙へ射影
すると：

| 指標 | E（射影前、256語） | E（34語彙へ射影） |
|---|---|---|
| 生成延べ | 34,570 | 5,851 |
| MATCH | 3,241 | 3,241（不変） |
| LOGIC_ONLY | 31,329 | 2,610 |
| SHOGI_ONLY | 2,167 | 2,167（不変） |
| **一致率** | **59.93%** | **59.93%（不変）** |

**重要な発見**：一致率の計算式 MATCH/(MATCH+SHOGI_ONLY) は
**LOGIC_ONLYを分母に含まない再現率（recall）であるため、34語への射影
を行っても一致率の数値自体は変化しない**（MATCH・SHOGI_ONLYはどちらも
「擇日象意側の期待集合」を起点に数えるため、擇日象意側に無い語である
34語彙外の語がどれだけ生成されてもMATCH・SHOGI_ONLYには影響しない）。
つまり**ALL型の語彙過拡張（256語）はLOGIC_ONLYの絶対数（見た目の
「ノイズの多さ」）を大きく水増ししているが、56.3%/59.9%という一致率
低下の直接の数値的原因ではない**（3章で確認したverdictフィルタの
影響の方が一致率そのものへの影響が大きい）。この点は次章以降の
俱不取分析と合わせて評価する必要がある。

## 10. 「俱不取」の原文上の意味（再確認）

`docs/takujitsu_activity_design.md`1.4〜1.6節（既存の原本画像確認済み
セクション）から、以下が既に確定していた：

- 擇日象意.pdfの各行は `[干支]日【憲宜】[用事…]【協紀】[仝／全／俱不取／加+用事…]`
  という構造。
- 【憲宜】＝憲書由来の宜リスト。【協紀】＝協紀辨方書由来で、常に
  「憲宜への追加（加）」「憲宜と同一（仝/全）」「両方とも無し（俱不取）」
  のいずれかのパターンしか取らない。
- **「俱不取」＝【憲宜】【協紀】の両方とも使える用事が無い、という
  2つの歴史的資料（憲書・協紀辨方書）自身の編纂上の結論**であり、
  「その日の吉凶の論理演算結果として自動的に0になる」ものではない。
- 擇日象意.pdf全体を通じて「忌」の文字は一度も出現しない（【憲宜】
  【協紀】とも宜のみを記録する資料）。

**結論（本フェーズでの再確認）**：選択肢A〜Dのうち、**A（その日の宜を
完全に0にする）が原文の字面には最も近いが、これは「２つの歴史的資料が
独自に判断した結果」であって、「神殺象意.pdfのEXCEPT型（餘事皆忌）＋
ALL型（諸事皆宜）を突き合わせた論理演算の結果」ではない**。擇日象意.pdf
（憲書・協紀）と神殺象意.pdf（日家神殺宜忌）は**別々の編纂資料**であり、
前者の「俱不取」という結論に、後者の個々の神殺の宜/忌がどう反映されて
いるか（あるいはいないか）を直接結びつける記述は、神殺象意.pdf・
擇日象意.pdfのいずれにも見当たらない。したがって、**「俱不取」を
神殺象意.pdfベースのengineで100%再現できることを前提にするのは、
そもそも資料の性質上、無理がある**という可能性が高い。

## 11. ALL型とEXCEPT型が同時成立する場合の原典規則

俱不取115行のうち、ALL型吉神（天徳等）が成立していた12行では、必ず
何らかのEXCEPT型凶神も同時に成立していた（105/115が母集団のため）。
この「ALL型（諸事皆宜）とEXCEPT型（餘事皆忌）が同一日に競合する」
ケースについて、神殺象意.pdfに優先関係・解除・無効化の記述があるかを
確認した。

**唯一確認できた記述は月破のみ**：「德神臨此失力，不能爲福，故即與
『德合』併，猶忌」（月破という特定の神殺について、徳合＝ALL型吉神群と
併存しても徳神の方が力を失う＝凶神優先、という個別の明記）。これは
月破という**個別の神殺**についての記述であり、他の10のEXCEPT型凶神
（死神・劫殺・災殺・月殺・月刑・月厭・四廢・上朔・四離・四絶）や、
ALL型吉神とEXCEPT型凶神の組み合わせ全般についての一般原則としては
神殺象意.pdfに記載が無い。

**結論：ALL型とEXCEPT型が同時成立した場合の一般的な優先関係は原典上
未確定**。月破以外について「凶神優先」を一般化することは推測になるため
行わない（resolution/rules.tsも月破以外への優先ルールを追加していない
＝前フェーズの実装方針のまま）。

## 12. resolutionが俱不取へ与えた影響

9章のとおり、EXCEPT型凶神11神のうち解除ルール（resolution/rules.ts）
を持つのは月刑（No.9a/9b）と月厭（No.8）のみ。俱不取115行における
EXCEPT型凶神の延べ成立184件中、cancelled化したのは4件のみで、俱不取
115行の分類結果（7章）を動かすほどの規模ではない。

事前調査（`docs/takujitsu_shinsatsu_shogi_audit.md`）はresolutionを
一切適用しないraw occurrenceベースの集計だったため、この点でも
前回・今回は比較の前提が異なっていたが、**実際の影響は軽微**（俱不取
115行の分類を変えるほどの規模ではない）であることを確認した。

## 13. 今後の正式検証指標（2種類に分離）

今回の分析結果を踏まえ、今後は以下の2指標を明確に分離して報告する
（同じ「一致率」という言葉で混同しない）：

### ① SOURCE VALIDATION（原典再現性検証）
神殺象意.pdfの詳細宜が、擇日象意.pdf自身の固有語彙（34〜50語）を
どこまで再現するか。ALL型は擇日象意.pdf側の語彙へ投影して評価する
（本フェーズのステージA・E射影に相当）。この指標は「神殺象意.pdfという
一次資料の記述と、擇日象意.pdfという別の一次資料の記述が、独立した
検証としてどれだけ整合するか」を測るものであり、**アプリの実装品質を
直接測るものではない**。

### ② APP EVALUATION（最終アプリ評価）
最終アプリ（神殺＋resolution＋十二建除＋二十八宿）が、ActivityDefinition
全256語の空間で、擇日象意.pdfの記述をどこまでverdict="good"として
再現するか（本フェーズのステージC〜Eのverdict列に相当）。この指標は
「ActivityDefinitionという広い語彙空間」「verdictという忌との相殺を
含む厳密な判定」「擇日象意.pdfという宜専用・忌を記載しない資料」という
性質上、①より低い数値になることが構造的に避けられない。

**①と②を同じ数字として比較しない**（今回の混同の再発防止）。
