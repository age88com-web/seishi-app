## 1. 用語の整理

**2026-09-09追記：本節は当初「本文だけでは確定できない」保留事項として
書かれていたが、講義上の正式な用語定義として下記のとおり確定した
（ユーザーからの明示的な指示による。docs/takujitsu_decisions.md にも
同内容を記録済み）。以降のルール一覧（2章）はこの確定定義を反映して
更新している。**

### 1.1 「徳合」の正式定義（確定）

解除・相殺・増悪ルールでいう「徳合」は、以下の6神殺の**いずれか一つ**が
成立していれば「徳合あり」と判定する（OR条件）。

> 徳合 ＝ 天徳 OR 天徳合 OR 月徳 OR 月徳合 OR 歳徳 OR 歳徳合

いずれも吉神として実装済み（天徳・天徳合・月徳・月徳合・歳徳・歳徳合は
すべて吉神Group1）。この6神殺のいずれかが `kichijin` に含まれていれば
「徳合あり」とする共通判定 `hasDeHe(kichijin)` を解除ロジック側に1つだけ
用意し、各ルールで6神殺を重複列挙しない設計とする（7章参照）。

**本文の記述との関係（重要な注記）**：擇日テキストp.18（2番月破の項）には
以下の記述があり、これは今回確定した6項目の定義とは**構成が異なる**。

> ※徳合とは天徳（合）・天赦・天願・月徳（合）の4つ。

このp.18の脚注は「天徳(合)・天赦・天願・月徳(合)」の4種（天赦・天願を
含み、歳徳・歳徳合を含まない）であり、今回確定した「徳合＝天徳・天徳合・
月徳・月徳合・歳徳・歳徳合（天赦・天願を含まない）」とは範囲が異なる。
これは講義上の正式な用語整理（赦願＝天赦・天願を独立の枠として切り出し、
徳合＝「徳」のつく6神殺に統一する）によるものであり、p.18の脚注はあくまで
**月破（2番）という個別項目の中でのローカルな言い換え**として扱う。
月破の解除条件（ルールNo.4a／4c）は今回確定した共通の「徳合」概念とは
別に、p.18本文が直接列挙する6神殺（天徳／天徳合／天赦／天願／月徳／
月徳合）をそのままのローカル条件として実装する（3.4節参照）。同様に
1番月建（小時）の解除条件（天徳(合)・天赦・月徳(合)・月恩・四相）も、
本文が独自に列挙した組み合わせであり、共通の「徳合」を流用しない
（月恩・四相を含み、歳徳・天願を含まない独自セットのため）。

### 1.2 「赦願」の正式定義（確定）

解除・相殺・増悪ルールでいう「赦願」は、以下の2神殺の**いずれか一方**が
成立していれば「赦願あり」と判定する（OR条件。ANDではない）。

> 赦願 ＝ 天赦 OR 天願

擇日テキストp.4（11番天願の項）の「赦願（天赦・天願）は「諏吉述正」には
最も吉で凶をとくと書かれている」という記述が、この定義の直接の根拠。
天赦・天願はいずれも吉神Group1で実装済み。共通判定 `hasShagan(kichijin)`
を1つ用意する（7章参照）。

### 1.3 「六合」の正式定義（確定）

解除・相殺・増悪ルールでいう「六合」は、地支の六合関係をその場で新たに
計算するのではなく、**既に吉神として実装済みの「六合」という神殺が
その日成立しているかどうか**（`raw.kichijin` に `"六合"` が含まれるか）
で判定する。

> 六合あり ＝ raw.kichijin.includes("六合")

六合は吉神Group3で実装済み（三合・六合・五合・鳴吠・鳴吠對のうちの1つ、
月建と日辰の支合）。新しい地支六合の計算ロジックを解除レイヤー側に
追加することはしない（既存の吉神ロジックをそのまま再利用する）。

### 1.4 「徳合・赦願」のような複合表現の扱い方（確定方針）

本文には「徳合」「赦願」の両方が並記される表現が複数あるが、**両者を
結ぶ日本語の表現（「一緒になれば」「合わさると」「あわさると」「と」の
有無）によって、OR（いずれか）なのかAND（両方）なのかが異なる**ため、
一律にOR/ANDを決め打ちしない。

- 明示的に「一緒になれば」「合わさると」「あわさると」という**共起を
  意味する言葉**が使われている場合 → 徳合(OR6) **AND** 赦願(OR2)。
- 明示的に「と」で結ばれている場合（例：「徳合と天願」）→ 本文の語順
  どおり、勝手にORへ変換せず**両者の連言（AND）を維持する**。ただし
  この場合の対象は「赦願」（天赦・天願のOR）ではなく、本文が明示した
  片方の語（例：天願のみ）である点にも注意する（3.5節、ルールNo.18）。
- 上記のような共起を示す言葉が無く、単に「・」で列挙されているだけの
  場合（例：「徳合・赦願が来たら」）→ 本文の文脈上、いずれか一方で
  成立すると読むのが最も literal（追加の接続語が無いため）と判断し、
  徳合(OR6) **OR** 赦願(OR2) として扱う（3.5節、ルールNo.14・17参照。
  ルールNo.17は「赦願」ではなく「天願」単独との組み合わせ）。

この扱い方によって、今まで「徳合」「赦願」の意味や結合方法が不明として
pending にしていたルールのうち、本文の他の条件まで確定しているものは
2章で正式な解除・増悪ルールとして格上げした（3.5節に一覧）。

### 1.5 関係の種類（本ドキュメントでの分類）

| 種類 | 意味 |
|---|---|
| 解除 | 対象の凶神が実質的に無効になる（凶意が消える） |
| 凶性軽減 | 完全には消えないが、一部の用途・行為に限り緩和される（例：ビジネスの「攻め」は凶のまま） |
| 増悪 | 凶意がさらに強まる（通常の「解除」役の吉神が、特定の凶神に限って逆に強める） |
| 条件付き解除 | 特定の月・季節・組み合わせなど、限定条件下でのみ解除される |
| 例外（構造的） | 対象凶神の成立条件そのものに内在する除外規定（外部の吉神による解除ではない） |
| その他 | 上記に当てはまらないもの（説明的記述、活動限定の参照表など） |

### 2.x 検討したが「ルール」として採用しなかったもの

- **無禄（24番）「解除」の語**：「忌：諸事宜しからず。特に祭祀、解除など」
  （p.29）。ここでの「解除」は凶神を打ち消す動作ではなく、忌むべき
  **活動としての「解除（お祓い・厄除け）」**を指す（無禄日にはお祓いを
  行うこと自体を避けるべき、という意味）。凶神解除ルールではない。
- **五墓（19番）「解除」の語**：「忌：上官、結婚、納采、嫁娶、進人工、
  搬移、安床　解除、救医、修造、上梁…」（p.26）。同様に忌むべき活動
  としての「解除」であり、五墓自体の解除ルールではない。
- **歳徳・歳徳合（5番）の「良くない霊がいるなどでこの日に解除するのも
  良い」（p.2）**：歳徳日が「解除（お祓い）」という活動を行うのに適した
  日である、という意味。凶神を打ち消す規則ではない。
- **月刑・天賊の月建との近接記載**：「劫殺と対になっている」（p.23、
  遊禍の項）は天賊・劫殺の**概念的な対応関係の説明**であり、「劫殺が
  あれば天賊がどうなる」という操作可能なルールではないため対象外。
- **定日（死気、4番）の三合免除**：「戊日が月建と三合になる→これは
  吉日なので死気にはならないと古典には書かれている。しかし避けた方が
  無難で、定日はすべて凶日ととらえた方がよい。」（p.19）。本文が
  明示的にこの例外を**採用しない**よう推奨しているため、解除ルールとは
  みなさない（凶神Group1の実装もこの推奨に従い、例外を反映せず全件を
  死気として扱っている。現状の実装のままでよい）。
- **陰陽不將（24番、吉神）の「上吉／次吉」区分**（p.11）：不將日が
  天徳・月徳・天徳合・月徳合・母倉と重なれば「上吉」、月恩・續世・
  人民合・日晨と月建の合と重なれば「次吉」という**吉神同士の格付け
  強化**の規則。凶神の解除・増悪ではなく、吉神の「グレード」を上げる
  仕組みのため本ドキュメントのスコープ外（将来、吉神の重要度・優先度
  付けを扱う段階があれば参照する）。

## 3. 特に重要な調査結果

### 3.1 「赦願」「徳合」「六合」の確定（2026-09-09、講義上の正式仕様）

以前は1.1〜1.2節で「本文だけでは確定できない」保留事項としていたが、
ユーザーからの明示的な指示により、以下を講義上の正式な用語定義として
確定した。

- **赦願 ＝ 天赦 OR 天願**（どちらか一方の成立で「赦願あり」。ANDではない）
- **徳合 ＝ 天徳 OR 天徳合 OR 月徳 OR 月徳合 OR 歳徳 OR 歳徳合**
  （いずれか一つの成立で「徳合あり」）
- **六合 ＝ 吉神「六合」の成立**（`raw.kichijin.includes("六合")` で判定。
  地支六合をresolution側で新たに計算しない）

「徳合・赦願」のような複合表現のAND/ORは、本文の接続表現（「一緒に
なれば」「合わさると」「あわさると」＝AND、明示的な「と」＝原文の連言を
維持、それ以外の単純な「・」列挙＝OR）に従って個別に確定した（1.4節、
詳細は各ルールの5.条件を参照）。この結果、以前pendingだったルールの
うち7件（No.8・12・14・17・18・20・21）が正式な解除・増悪ルールとして
確定・実装可能に格上げされた（5章）。

なお、この確定した「徳合」6項目は、擇日テキストp.18が月破（2番）の
文脈で示すローカルな「徳合とは天徳（合）・天赦・天願・月徳（合）の
4つ」という定義とは**範囲が異なる**（天赦・天願を含まない代わりに
歳徳・歳徳合を含む）。この違いは講義上の用語整理によるものであり、
月破（ルールNo.4a／4c）・月建（ルールNo.3）はp.18本文が直接列挙する
独自の組み合わせをそのまま使い、共通の「徳合」定義を流用しない
（詳細は1.1節）。

### 3.2 月破の例外の調査結果

原文（p.18、再掲）：

> 子・午月→災殺（子午日）　未・申月→月刑（丑寅日）　卯・酉月→災殺
> （卯酉日）　上記の日は凶日とならない。

この一文だけでは、以下の3つの解釈のどれが正しいか本文から断定できない。

1. **月破そのものが成立しない**（月破の occurrence 自体がこの条件下では
   そもそも発生しないという、月破の定義の一部としての除外規定）
2. **月破は成立するが、解除・相殺レイヤーで凶性だけが打ち消される**
   （occurrence としては存在し続けるが、最終評価では凶としない）
3. **その日全体の総合判定（他の神殺との組み合わせを含めた最終評価）が
   「凶日ではない」という意味であり、月破という個別の凶神の成否とは
   別次元の話**

「凶日とならない」という表現は「月破とならない」ではなく「（その）日が
凶日とならない」という**日単位の総合評価**を指しているように読めるため、
解釈3の可能性も排除できない。一方で、この一文が月破の項目の中に
直接書かれていることから、解釈1（月破自体の除外）である可能性も高い。

**結論**：本文だけでは一意に確定できないため、指示どおり
**occurrence detectionは現状維持**（月破は引き続き成立したまま返す）とし、
本台帳では**保留**として記録する。将来この文言の意図が確認できた場合に
実装する。

なお、これとは別に「下記の日は徳合がきても解除されない」
（4月癸亥・10月丁巳＝陰陽交破、6月癸丑・12月丁未＝陽破陰衝）という
**別の例外**が同じ項目内に存在する（ルールNo.4c）。これは「解除されない
日がある」という記述であり、上記の「凶日とならない」例外（ルールNo.4b）
とは完全に別の規定である。両者を混同しないこと。

### 3.3 その他の全体的な傾向

- 徳合・六合・天願・赦願等による「解除」が最も多いパターンだが、
  **同じ吉神の組み合わせが逆に「増悪」として働く例が複数存在する**
  （遊禍・觸水龍・氣往亡・四離四絶・八節日・土王用事・土符）。
  実装時に「徳合系＝常に解除」という誤った一般化をしないよう注意が
  必要（本ドキュメントの各ルールを個別に参照すること）。
- 凶神同士の相互作用（吉神が絡まない）は月刑×月破（増悪）の1件のみ
  確認できた。
- 「土旺」の正体は結局確定できなかった（凶神第5・第6グループに続き
  今回も未解決）。31番「土王用事」との関係は状況証拠（p.4の「土王用事
  つまり土用」という明記、p.32伏社の「社とは土旺のことを指す」という
  記述）はあるが、本文が明示的に同一と述べていないため、引き続き
  「関連性は疑われるが確定できない」という保留状態を維持する。
- 「解除」という単語自体が、（a）凶神を打ち消す作用、（b）お祓い・
  厄除けという活動そのもの、の2つの意味で使われており、本文を読む際は
  文脈で区別する必要がある（2.x節参照）。誤って後者を前者として抽出
  しないよう、今回のルール一覧では区別済み。

## 4. 洪氏錦嚢解説（p.46-64）について

擇日テキストの後半（p.46〜p.64）に「洪氏錦嚢 解説」という章があり、
避宅出火・動土平基・起基定硬・竪柱上梁・蓋屋合脊・入宅歸火・安碓・
安門・造畜柵牧養・開帳店肆・出行求財・修宅・安葬・造船行舟・上官赴任・
結婚納采・裁衣合帳・安床など、**用途（活動）ごとの忌例一覧**が列挙
されている。

この章にも「〇〇吉神があれば用いて良い」「〇〇吉神に押さえられれば
（抑えられれば・制御されれば）良い」という、神殺同士の関係を示す表現が
多数出現する。しかし、この章は上記2章の各項目本文とは性質が異なる。

- ほとんどの記述が「**吉神にあうなど条件が合えば**用いて良い」という
  形で、**具体的にどの吉神かを名指ししていない**（1章のような
  「天徳（合）・天赦・月徳（合）」のような明示的な列挙がない）。
- 対象は用途（活動）ごとに変わり、同じ凶神でも活動によって「用いては
  いけない」「問題ない」「条件が合えば良い」と評価が異なる
  （用途判定フェーズの領域）。
- 「白虎」「建星白虎」「虎中」「朱雀」「雀中」「留紳」「大安」「空亡」
  「小吉」など、擇日テキストの日家凶神1〜53番・日家吉神一覧には**存在
  しない別体系の神殺名**が多数登場する（本プロジェクトの実装範囲外）。

一部、本ドキュメント2章の内容を裏付ける記述もある（例：「「気往亡」
「四離絶」「二至二分日」大凶。」p.52＝氣往亡・四離四絶・八節日が重い
凶であることの再確認）が、新しい操作可能なルールとしては採用できる
ものが見当たらなかった。

**結論**：この章は具体的な吉神を名指ししない曖昧な記述が中心であり、
かつ「活動（用途）ごとの可否判定」という性質上、`docs/takujitsu_progress.md`
の実装順序4番「用途判定」フェーズで扱うべき内容と判断し、今回の
「神殺解除・相殺」ルール台帳には含めない。将来、用途判定フェーズに
着手する際に改めてこの章を参照すること。

## 7. 推奨する解除判定データ構造（設計案。未実装）

### 7.1 基本方針

- 既存の `ShinsatsuResult { kichijin: string[]; kyojin: string[] }` は
  **一切変更しない**（occurrence detection の出力形状を維持）。
- 新しいレイヤーは、この `ShinsatsuResult` を**入力として受け取り**、
  別の型を**出力する純粋関数**として設計する。既存の
  `resolveKichijin*` / `resolveKyoushinGroup*` を呼び出す側
  （`calculateShinsatsu` / `calculateTakujitsu`）を変更する必要は
  あるが、既存の判定ロジック自体には触れない。

### 7.2 型設計案

```ts
// src/lib/takujitsu/resolution/types.ts（案。まだ作成していない）

/** 解除・相殺・増悪を適用した後の1神殺あたりの状態。 */

  | "cancelled"   // 解除された（凶意が消える）
  | "reduced"     // 凶性軽減（完全には消えないが一部緩和。用途限定の注記を伴うことが多い）
  | "aggravated"  // 増悪（凶意が強まる）

  reason?: string;

}

export interface ResolvedShinsatsuResult {

```

### 7.3 ルールテーブルの表現案

各ルールをデータ（コード内の定数配列）として持ち、判定ロジックは
共通の小さなインタープリタ1つで済ませる方針を想定する（ルールごとに
個別関数を書くと本ドキュメントの曖昧な条件を実装時になし崩し的に
確定させてしまうリスクがあるため、宣言的なデータ構造にして
「未確定の解釈はコードにもコメントで残す」ことを徹底しやすくする）。

1.1〜1.3節で確定した「徳合」「赦願」「六合」は、個別ルールに6神殺・
2神殺を毎回列挙するのではなく、共通の名前付きグループとして1箇所に
定義し、`requires` から参照する。

```ts
export type RelationKind = "cancel" | "reduce" | "aggravate";

/** 1.1〜1.3節で確定した共通グループ。各ルールはこれを参照するだけで、
 *  神殺名を個別に列挙しない。 */
export const DEHE_GROUP = ["天徳", "天徳合", "月徳", "月徳合", "歳徳", "歳徳合"] as const; // 徳合（OR6）
export const SHAGAN_GROUP = ["天赦", "天願"] as const; // 赦願（OR2）

export interface ResolutionRule {
  /** 本ドキュメントの「ルールNo.」。 */
  id: string;
  /** 対象となる凶神（複数可。例：四撃〜五虚の6項目）。 */
  targets: string[];
  /** 発動に必要な他の神殺（吉神・凶神いずれも可）。共通グループ（DEHE_GROUP等）または個別の神殺名を渡す。 */
  requires: {
    /** 名前の配列。共通グループをそのまま渡してよい。 */
    names: readonly string[];
    /** "any"＝いずれか1つで成立、"all"＝すべて必要（今回確定した17ルールの中では使用しない。将来の拡張用）。 */
    mode: "any" | "all";
  }[];
  /** requires の複数グループを how で連結する（"and"＝全グループ成立、"or"＝いずれかのグループ成立）。 */
  combine: "and" | "or";
  kind: RelationKind;
  /** 本ドキュメントの該当ページ。 */
  page: string;
  /** 保留中かどうか（true の間は判定ロジックを発火させず "pending" を返す）。 */
  pending: boolean;
}
```

例（月厭・厭對、ルールNo.8。「徳合、赦願が一緒になれば解除される」＝
徳合(OR6) AND 赦願(OR2)、1.4節の方針で確定済み）：

```ts
{
  id: "8",
  targets: ["月厭", "厭對"],
  requires: [
    { names: DEHE_GROUP, mode: "any" },   // 徳合
    { names: SHAGAN_GROUP, mode: "any" }, // 赦願
  ],
  combine: "and", // 「一緒になれば」＝両グループとも成立が必要
  kind: "cancel",
  page: "p.20",
  pending: false, // 定義確定済み（3.1節）
}
```

例（觸水龍、ルールNo.17。「徳合・天願がくると更に忌む」＝徳合(OR6) OR
天願単独。共起を示す接続語が無いためORとして確定）：

```ts
{
  id: "17",
  targets: ["觸水龍"],
  requires: [
    { names: DEHE_GROUP, mode: "any" },
    { names: ["天願"], mode: "any" },
  ],
  combine: "or",
  kind: "aggravate",
  page: "p.27",
  pending: false,
}
```

例（四離・四絶、ルールNo.18。「徳合と天願がきたら尚忌む」＝本文が明示的に
「と」で結んでいるため、ORへ変換せずANDのまま）：

```ts
{
  id: "18",
  targets: ["四離", "四絶"],
  requires: [
    { names: DEHE_GROUP, mode: "any" },
    { names: ["天願"], mode: "any" },
  ],
  combine: "and", // 本文の「と」をそのまま維持
  kind: "aggravate",
  page: "p.30",
  pending: false,
}
```

### 7.4 適用順序についての注意（設計上の論点。未確定）

同じ凶神に対して複数のルールが同時に発動しうる場合（例：五墓に
月徳条件付き解除と、もし将来「土旺」ルールが確定すれば四撃〜五虚グループ
への増悪ルールが重なる可能性）、cancel と aggravate のどちらを優先する

- **A**：現在の情報だけで安全に実装できる（resolutionで実装済み、または

- **B**：将来の用途判定レイヤーで扱うべき（神殺そのものの解除ではなく、

- **C**：本文が曖昧、または現在のresolution schema（occurrence名の配列
  のみを入力とする）では判定に必要な情報が得られず、保留

### 12.1 No.7（血支・閉日）の最終結論

原文（p.20）再確認：「吉日が来ていれば解除できる。歳徳・合、月徳・合、
赦願など」。

「など」は依然として非網羅的である。既存方針（No.19で採用した「部分的
有効化はしない」）を本ルールにも一貫して適用する。歳徳・歳徳合・月徳・
月徳合・赦願（OR2）という判明している4種だけを実装すると、本文が
示唆する「など」の範囲（未知の追加候補）を反映できないまま「確定」と
表示してしまうことになり、正確性を欠く。

**結論：C（保留）を維持。** `resolution/rules.ts` の該当ルール（id:"7"）
は変更なし（`pending: true` のまま）。

### 12.2 No.19（九空）の最終結論

原文（p.28）再確認：「六合・月建（地支の蔵干が合となるため冲が解除）・
徳合がくれば解除」。

今回、「月建」という語の擇日テキスト内での用例をあらためて全件確認した
（既存の「月令」の見出しとしての用法は除き、独立した語としての「月建」
の使用箇所）。結果、少なくとも2つの読み方が併存しうることが分かった。

1. **「月建（小時・土府）」という名前の凶神（1番）そのものを指す説**：
   洪氏錦嚢解説p.48（起基定硬忌例）に「「月建」凶神にあえばますます
   凶意が増し，吉神にあって押さえられれば用いて良い。」という一文があり、
   ここでは「月建」が他の named 凶神（「月破」「天火」等）と並んで
   **独立した1つの凶神名**として扱われている。この用例は、1番の項目
   タイトル「月建（小時・土府）」と一致する。この読み方であれば、
   九空の項の「月建」も同じ named occurrence（コード上は「小時」として
   実装済み、凶神Group1）を指しており、既存の occurrence フラグ
   （`kichijin`/`kyojin` に「小時」が含まれるか）だけで判定できる。
2. **「地支の蔵干が合となる」という機序の主語としての用法**：直後の
   括弧書き「（地支の蔵干が合となるため冲が解除）」は、支合（地支同士が
   合になる関係）の説明として自然に読め、これは16番「六合（月建と日辰が
   支合する日）」の定義とも整合する。この読み方だと、括弧書きは「六合」
   の機序を補足しているとも解釈でき、「月建」が六合とは別の独立した
   第三の条件ではなく、六合の言い換え・注釈である可能性も排除できない。

この2つの読みは、どちらも本文の別の箇所（1つ目は洪氏錦嚢解説の実際の
用例、2つ目は16番六合自身の定義）と整合するため、**本文の用例だけからは
一義的に一方へ絞り込めない**。一般知識で「小時と六合のどちらが正しい
古典的解釈か」を補って決めることはしない。

**結論：C（保留）を維持。** `resolution/rules.ts` の該当ルール（id:"19"）
は変更なし（`pending: true` のまま）。六合・徳合の部分だけを切り出す
部分的有効化もしない（12.1節と同じ理由）。
