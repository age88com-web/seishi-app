# 擇日実例 → 擇日象意 対応関係の検証

最終更新：2026-09-09（初版。16サンプルでの構造検証。コード変更なし）

---

## 0. 本ドキュメントの位置づけ

ユーザーからの重要な仕様情報「擇日象意.pdfは擇日実例.pdfをベースに
作られている」を踏まえ、

```
擇日実例（その月＋日干支に記載される吉神・凶神）
  ↓
各神殺の象意（ActivityProfile）
  ↓
擇日象意の宜（憲宜・協紀）
```

という対応関係が成立するか、`docs/takujitsu_shogi_validation.md`
（前フェーズ、CalendarEngineから成立させた全神殺・十二建除・二十八宿を
合算して比較）とは異なるアプローチで検証した。**十二建除・二十八宿は
今回の比較には含めていない**（擇日実例に記載が無いため）。コード変更
は一切行っていない（`CalendarEngine`・神殺occurrence・`resolution`・
`activityProfiles`・`evaluateActivities`・`jianchu`・`shuku28`はすべて
今回未変更）。

---

## 1. 検証方法

### 1.1 擇日実例.pdfの構造

`docs/source/擇日実例.pdf`（24ページ、「吉凶神煞一覧表」）は、12ヶ月
（節気で区切られる節月。例：正月＝立春〜雨水）×六十干支＝720行の表で、
各行に

```
[干支][納音五行][義/寶/制/伐/専/賓][十二直]日【吉神】...【凶神】...
```

の形式でその日に成立する吉神・凶神の名前がすべて列挙されている。
さらに各月の見出しに「初七日長星」「立春前一日四絶」「後七日往亡」の
ような**暦日番号・節気基準の項目は行本体ではなく月ヘッダーの注記**として
別記されている。これは、擇日実例.pdfの行本体が**monthBranch＋日干支
だけで決まる神殺（Tier1）のみ**を扱い、農暦日・節気タイミング依存の
神殺は別枠で扱っていることを意味する（前フェーズ`takujitsu_shogi_validation.md`
1.4節で述べた「年干・農暦月・節気・宿値日依存の神殺は擇日象意.pdfの
抽象表には本来含まれない」という仮説と整合する）。

抽出は`docs/source/擇日テキスト.pdf`と同じ位置ベースの方法を用いた
（`tests/fixtures/jitsurei_samples.json`）。OCR/抽出時の異体字（未←末、
殺←煞、氣←気、將←将、搖←揺）は座標抽出で原文を確認したうえで、既存の
確定済み方針（`docs/takujitsu_decisions.md`「殺／煞のような異体字は
擇日テキストの表記を優先し、実例PDF側の異体字は検証用fixtureでのみ
許容する」）に沿って比較用スクリプト内でのみ正規化した（`ActivityDefinition`
やoccurrence名そのものは一切変更していない）。

### 1.2 サンプル選定

前フェーズ（`takujitsu_shogi_validation.md`）で選んだ40サンプルのうち、
擇日実例.pdf側で抽出できた16行を選んだ（OCR/抽出上の欠落は約16行/720、
2%程度）：12ヶ月からの甲子・癸巳・癸亥系列を中心に、俱不取サンプル
（正月乙丑・八月丁卯）、宜が多いサンプル（五月丙申・十二月辛酉）を含む。

### 1.3 比較の枠組み

各サンプルについて、`monthBranch`＋`dayStem`＋`dayBranch`が一致する
実在日を検索し（前フェーズと同じ方法、`tests/fixtures/gen_jitsurei_analysis.ts`）、
その実在日で`calculateShinsatsu()`を実行し、擇日実例に記載された神殺
（Tier1のみ）と比較した（2章）。さらに、擇日実例に記載された**吉神
だけ**（凶神は含めない）から`ActivityProfile.favorableActivityIds`を
合成し、擇日象意.pdfの憲宜／協紀と比較した（3章）。

## 2. occurrence engineとの一致度（擇日実例 vs calculateShinsatsu）

| | 擇日実例側件数 | MATCH | ENGINE_ONLY | JITSUREI_ONLY | 一致率 |
|---|---|---|---|---|---|
| 吉神 | 78 | 77 | 54 | 1 | **98.7%** |
| 凶神 | 53 | 51 | 6 | 2 | **96.2%** |

**occurrence detection（吉神Group1〜6・凶神Group1〜6）は擇日実例.pdfと
極めて高い精度で一致した**。これは前フェーズ・既存の単体テスト
（各グループの「既知の差異N件は別枠」という既存の注記）とも整合する、
独立資料による強い検証結果である。

### 2.1 ENGINE_ONLY（engineが多く出す神殺）

吉神ENGINE_ONLYの内訳（延べ54件）は、`神在`(14)・`義日`(8)・`兵吉`(8)・
`天貴`(6)・`専日`(4)・`催官`(3)・`天福`(3)・`枝德`(2)・`七聖`(2)・
`續世`(1)・`母倉`(1)・`兵福`(1)・`大明`(1)に集中していた。これらは
**`docs/takujitsu_shogi_validation.md`3.3節で「擇日象意.pdfの憲宜表に
一度もMATCHしなかった吉神」として特定した項目とほぼ完全に重なる**。
凶神ENGINE_ONLYは`無禄`(4)・`兵禁`(1)・`地嚢`(1)のみで、件数も少ない。

これは重要な確証：**擇日実例.pdfと擇日象意.pdfは、擇日テキスト.pdfが
紹介する69件の吉神のうち同じ「核となるサブセット」だけを採用している**
ことが、2つの独立資料（擇日実例・擇日象意）から一貫して確認できた。

### 2.2 JITSUREI_ONLY（engineが出さない、擇日実例だけにある神殺）

- 吉神：`災殺`1件（正月ではなく八月丁卯で発生。原文自体に
  「丁卯...【吉神】天火五合明堂鳴吠對」と、通常は凶神の別名である
  「天火」が【吉神】欄に印字されている。座標抽出で原文を再確認したが
  印字そのものがこの形になっており、抽出誤りではなく**原典側の
  記載の揺れ・誤植の可能性がある1件の例外**として記録するに留めた
  （断定しない）。
- 凶神：`血支`（血忌）2件（九月癸巳・十月癸亥）。いずれも実例側が
  「血忌」を記載しているが、当該実在日のengine側十二直判定は「血支
  （閉日限定）」の条件（閉日）と矛盾する十二直（建日・平日相当）に
  なっていた。原因はサンプル数16では特定できず、「I. 原典から原因を
  特定できない」として保留する。

## 3. 「擇日実例の吉神→ActivityProfile→宜」と擇日象意の比較

十二建除・二十八宿を含めず、**擇日実例に記載された吉神だけ**から
`favorableActivityIds`を合成し、擇日象意の憲宜／協紀／combinedと比較した。

| 指標 | 件数 |
|---|---|
| 擇日実例の吉神から合成した宜（延べ） | 154 |
| 擇日象意側の総宜件数（延べ、辞書解決できたもの） | 133 |
| MATCH | 17 |
| うち憲宜とのMATCH | 15 |
| うち協紀とのMATCH | 2 |
| LOGIC_ONLY | 137 |
| SHOGI_ONLY | 116 |
| 一致率（MATCH／擇日象意側総宜） | **12.8%** |

前フェーズ（CalendarEngineの全神殺・十二建除・二十八宿を合算した場合）
の一致率15.5%と比べて**わずかに低下した**。これは、前フェーズのMATCHの
一部（十二建除4件・二十八宿1件・凶神の宜10件のうち一部）が、擇日実例に
記載された吉神だけの集合には含まれないためである。**つまり、「occurrence
の対象を擇日実例に記載された吉神だけに絞る」という操作だけでは一致率は
改善しなかった**。これは2章の結果（occurrenceの一致率は98.7%と非常に
高い）と合わせて読むと重要な意味を持つ：

**ボトルネックはoccurrence（どの神殺が成立するか）ではなく、
ActivityProfile（各神殺がどの用事を宜とするか）の網羅性にある**、
という結論を強く裏付ける。

### 3.1 SHOGI_ONLY（擇日象意にはあるが、実例吉神の象意からは出ない）

`docs/takujitsu_shogi_validation.md`3.4節で確認した「A/I分類（該当する
吉神・十二建除・二十八宿が現行データに一件も無い）」16語（裁衣・
立券交易・納畜・修倉庫・進人口・築堤防・経絡・整手足甲・掃舎宇・剃頭・
栽種・補垣塞穴・安床・平治道塗・修造動土・修飾垣墻）は、今回の「吉神
だけ」比較でも同様にSHOGI_ONLYとして再現された。これらは十二建除・
二十八宿を比較対象から外しても解消しない、**吉神象意プロファイル自体の
不足**であることが今回改めて確認できた。

### 3.2 俱不取行の構造（7章の核心）

擇日象意.pdf側が「俱不取」（憲宜・協紀とも0件）となる4サンプル
（正月乙丑・四月癸亥・五月甲子・八月丁卯）について、擇日実例側の
吉神・凶神を確認した。

| 月/干支 | 擇日実例の吉神 | 擇日実例の吉神から合成した宜（延べ） | 擇日実例の凶神 |
|---|---|---|---|
| 正月乙丑 | 明堂 | 家族会議・遠行（2件） | 五虚・土符・天賊・月殺・歸忌・血支 |
| 四月癸亥 | 天倉・寶光・金堂・驛馬 | 12件 | 四廢・往亡・月破 |
| 五月甲子 | 六儀・解神・金匱 | 5件 | 五虚・厭對・月破・災殺 |
| 八月丁卯 | 五合・明堂・災殺・鳴吠對 | 8件 | 五虚・月厭・月破・災殺 |

**重要な発見**：俱不取の4行すべてで、吉神は実際に成立しており
（0件ではない）、その象意から2〜12件の候補宜が合成できるにもかかわらず、
擇日象意.pdfは「俱不取」（用事ゼロ）としている。**「吉神が存在しない
から俱不取」という単純な構造ではない**ことが明確になった。

凶神側を見ると、4行中3行（四月癸亥・五月甲子・八月丁卯）に`月破`が、
4行中3行（正月乙丑・五月甲子・八月丁卯）に`五虚`が共通して出現して
いるが、いずれも4行全部には共通しておらず、単一の凶神が俱不取を
確定的に決定しているとは断定できない（サンプル数16のうち俱不取は
4件のみのため、統計的な確証には至らない）。`docs/takujitsu_resolution_rules.md`
にも「凶神が他の神殺の宜を打ち消す」という規則は記載されていない
（既存resolutionルールは吉神が凶神を解除・軽減・増悪する方向のみを
扱っており、逆方向＝凶神が吉神由来の宜を無効化する規則は今回参照した
擇日テキスト.pdfのどこにも見当たらなかった）。**したがって、「凶神の
忌用事だから宜から自動削除する」という新しいルールは作らず、「I. 原典
から原因を特定できない」として保留する**（ユーザー指示どおり、実例から
逆算した新規則は実装しない）。

## 4. 「擇日実例の神殺象意を単純合成すれば擇日象意になるか」の判定

**結論：ならない。** 理由は以下の2点に整理できる。

1. **occurrence自体はほぼ完全に一致する**（2章、吉神98.7%・凶神96.2%）
   ため、「どの神殺が成立するか」は問題ではない。
2. **擇日象意.pdfは、擇日テキスト.pdfが紹介する69件の吉神のうち
   「核」となる一部（天徳・月恩・母倉・天願・王官守相民日・鳴吠・
   驛馬・吉期・時陰・天倉・神在以外の…など）だけを採用しており**、
   かつ**採用された吉神についても、擇日テキスト.pdfに記載された象意
   （数個の例示的な用事）だけでは擇日象意.pdfの憲宜を再現するのに
   全く足りない**（3章、一致率12.8%）。

このため、単純な「occurrence合成」では擇日象意.pdfを再現できない。
ただし、**擇日テキスト.pdf内に「月＋日干支→用事」という直接規則は
見当たらなかった**（前フェーズ5章の結論を今回も覆す情報は得られな
かった）。したがって、擇日象意.pdfの実際の生成原理は、擇日テキスト.pdf
（今回のACTIVITY_PROFILESの原資料）よりも**遥かに詳細な象意情報**
（おそらく協紀辨方書・憲書などの原典そのもの）を持つ**別資料**を参照して
編纂されていると考えられる。この「別資料」の特定・追加入手は今回の
スコープ外である。

## 5. 最終報告（20項目）

1. **比較した行数**：16行（前回40サンプルのうち擇日実例側で抽出できたもの）
2. **擇日実例の吉神総数**：78件（延べ、Tier1のみ）
3. **擇日実例の凶神総数**：53件（延べ、Tier1のみ）
4. **occurrence engineとの吉神一致率**：98.7%（77/78）
5. **occurrence engineとの凶神一致率**：96.2%（51/53）
6. **実例吉神の象意から生成した宜件数**：154件（延べ）
7. **擇日象意の宜件数**：133件（延べ、辞書解決できたもの）
8. **MATCH**：17
9. **LOGIC_ONLY**：137
10. **SHOGI_ONLY**：116
11. **憲宜との一致**：15
12. **協紀との一致**：2
13. **俱不取行の構造**：4サンプルすべてで吉神は成立しており2〜12件の
    候補宜が合成できるにもかかわらず擇日象意は俱不取。単一の凶神による
    確定的な説明はできず（月破・五虚が複数行に共通するが全行共通では
    ない）、原典に明確な「凶神が宜を無効化する」規則も見当たらないため
    未解明のまま保留
14. **象意profileの不足**：`docs/takujitsu_shogi_validation.md`で特定
    済みの16語（裁衣・立券交易・納畜等）が、吉神象意だけに絞っても
    同様に再現不能なことを確認。擇日テキスト.pdfの象意記述が擇日象意.pdf
    に比べて簡略すぎることが根本原因と考えられる
15. **象意profileの過剰**：ENGINE_ONLYの大半（吉神54件中48件）は
    「擇日象意.pdfの憲宜表に採用されない吉神」（神在・義日・兵吉・
    天貴・専日・催官・天福等）由来で、occurrence自体は正しいが、
    実例・象意の双方でこれらの吉神が使われていないことが2つの独立
    資料で確認できた
16. **凶神・resolutionが宜に与える影響**：既存resolutionルールは
    吉神が凶神を解除・軽減・増悪する方向のみを規定しており、凶神が
    吉神由来の宜を無効化する規則は原典に見当たらなかった。俱不取の
    説明としては未確認のまま保留（新規則は作らない）
17. **擇日実例→擇日象意を単純合成で再現できるか**：できない。
    occurrenceはほぼ完全一致するが、①擇日象意が採用する吉神は擇日
    テキスト.pdfの69件中の一部のみ、②採用された吉神についても擇日
    テキスト.pdfの象意記述だけでは擇日象意の宜を再現するには不十分
18. **再現できない場合に不足する処理**：（a）擇日象意.pdfで実際に
    採用されている吉神の「核」サブセットの特定と、それに絞った
    プロファイル運用の検証、（b）裁衣・立券交易・納畜等16語について
    擇日テキスト.pdf以外の原典（協紀辨方書等）を追加参照できるかの
    調査、（c）俱不取の発生条件の追加サンプルでの検証
19. **次に実装すべき内容**：今回はコード変更なし。次フェーズ候補として、
    720行全件での本検証の再実行（統計的信頼性の向上）、擇日象意.pdfが
    採用する吉神「核」サブセットの確定、Tier1以外（歳徳・天願等）を
    含めた完全な擇日実例照合を推奨する
20. **docs更新結果**：`docs/takujitsu_jitsurei_shogi_analysis.md`を新規
    作成（本ファイル）。検証用データ・スクリプトは`tests/fixtures/`
    （`gen_jitsurei_analysis.ts`・`jitsurei_samples.json`・
    `jitsurei_analysis_results.json`・`jitsurei_shogi_compare.json`）に
    追加。既存コード（`src/`配下）は一切変更していない
