# 奇門遁甲 剋應モジュール実装仕様整理

## 1. 仕様の境界

- 唯一の仕様: 添付「剋應.pdf」の本文。
- 実装対象: 十干剋應、八門剋應、九星値時剋應、三奇到宮剋應の4種類。
- 実装対象外: 地支の剋應・八卦剋應。資料は存在に言及するだけで、本PDF内に4種類と同等の実装表を収録していない。
- 変更禁止: 排盤ロジック、CalendarEngine、七政四餘、既存UI。
- 不明事項は一般知識・他流派・推測で補完しない。資料上の異説・表記差は上書きせず併記する。

## 2. 共通データ方針

全レコードに最低限、次の項目を持たせる。

| 項目 | 内容 |
|---|---|
| `type` | `jikkan` / `hachimon` / `kyusei_jichi` / `sanki_tokyu` |
| `source_section` | PDF内の節名 |
| `source_tradition` | 資料本文が明示する典拠・系統。異説を分離するため必須 |
| `key` | 種類別の正規化判定キー |
| `name` | 資料に名称がある場合の名称。ない場合は `null` |
| `fortune_raw` | 資料に明示された吉凶表記を原文のまま保持 |
| `fortune_code` | 検索・表示用の正規化値。原文を置換しない |
| `body` | 判定本文。省略・要約せず保持 |
| `conditions` | 吉門・凶門、迫・墓・撃・刑、用途などの付加条件 |
| `exceptions` | 異説、原文差、男女差、条件反転等 |
| `notes` | PDF本文の訳注・語注・現代的補足 |

`fortune_code` は資料の表記からのみ作り、最低限 `good`（吉）、`bad`（凶）、`mixed`（半吉半凶・中平）、`conditional`（条件で変化）、`unspecified`（明示なし）を許容する。本文から独自に吉凶を推定しない。

## 3. 十干剋應

### 判定キー

`天盤奇儀 × 地盤奇儀`

- 対象は乙・丙・丁・戊・己・庚・辛・壬・癸の9奇儀。
- 基本組合せは9×9の81件。順序に意味があり、上下を入れ替えない。
- 甲は独立キーにしない。資料本文は「甲は戊の中に隠遁しているため、戊と甲は同じ」と説明する。

### 必須データ項目

- `heaven_stem`（天盤奇儀）
- `earth_stem`（地盤奇儀）
- `name`（各組合せの格名）
- `fortune_raw`（冒頭一覧表の○・△・×を含む）
- `body`（各表の「吉凶判断」全文）
- `conditions`（吉門・凶門、三吉門、生門・開門、迫・墓・撃・刑、星など）
- `gender_condition`（男吉女凶等が明記される場合）
- `purpose_condition`（求財、婚姻、病、訴訟、功名等が明記される場合）
- `notes`（本文後段の語注・格局説明）

### 例外・注意

- 冒頭の○・△・×一覧と個別本文を両方保持する。○は吉、×は凶、△は半吉半凶。
- 個別本文では、吉門・凶門や迫・墓・撃・刑によって吉凶が反転・増減する組合せがある。単一の真偽値に潰さない。
- `戊×丙（青龍返首）` は大吉大利だが、迫・墓・撃・刑で吉事が凶になる。
- `戊×丁（青龍耀明）` は吉利があるが、墓・迫でいざこざを招く。
- `乙×丙（奇儀順遂）` は吉星なら栄転・昇進、凶星なら夫妻反目・離別。
- `乙×己（日奇入墓）` は本文上凶だが、生門・開門を得れば地遁となる。
- `丙×丁（星奇朱雀）` には天遁の成立説明が付く。
- `丁×乙（玉女奇生）` には人遁の成立説明が付く。
- `庚×壬` は上格、`庚×癸` は大格として語注がある。
- `癸×癸（天網四張）` の後に「天盤奇儀の代わりに時干を加えて看る方法もある」と明記される。これは別方式なので、既定判定を黙って置換せず、`calculation_variant` として明示的に分離する。

## 4. 八門剋應

八門は開・休・生・傷・杜・景・死・驚。

### 判定モード

資料は次の3系列を別物として記載する。

1. 静應: 人盤八門 × 地盤八門
2. 静應: 人盤八門 × 天盤奇儀
3. 動應: 人盤八門 × 地盤八門

したがってキーは最低限 `mode + human_gate + counterpart_type + counterpart` とする。静應と動應を同一レコードに統合しない。

### 静應の意味と項目

- 人が空間から動かない用法。
- 資料本文は動土、住宅の修築を含む居住空間・周辺環境との関係を説明する。
- `mode: static`
- `human_gate`
- `counterpart_type: earth_gate | heaven_stem`
- `earth_gate` または `heaven_stem`
- `body`
- `fortune_raw`（明示される場合）
- `purpose_condition`

### 動應の意味と項目

- 門と閘が相対するとき、門（家）から出て路上で遭遇する兆應。
- 出行における時間・方位・移動距離と、遭遇現象・結果を扱う。
- `mode: dynamic`
- `human_gate`
- `earth_gate`
- `distance_li_raw`（例: 一里、十一里）
- `distance_metric`（資料が括弧内に示す換算値のみ。独自換算しない）
- `omen_body`（遭遇する人物・動物・音・事件等）
- `result_body`（「應ずる」後の結果が分離可能な場合）

### 例外・注意

- 「閘」は三奇（乙=日奇、丙=月奇、丁=星奇）のいずれかが休・開・生のいずれかと同居する「奇及閘合」と資料が定義する。この説明をキー条件または注記として保持する。
- 動應の距離は本文の里表記と括弧内メートル・km表記を両方保存する。
- PDF本文には、里の時代差・換算に関する注記がある。本文記載値を優先し、外部換算を導入しない。
- 八門自身の一般象意と、静應・動應の具体的本文を混同しない。
- 資料は八門剋應に諸説があることを説明するが、本章に収録した具体的事象を採用している。外部の「八門×八卦」説を追加しない。

## 5. 九星値時剋應

### 判定キー

`値符星 × 時支`

- 値符星: 天蓬・天任・天沖（本文中に天衝表記もある）・天輔・天禽・天英・天芮・天柱・天心。
- 時支: 子・丑・寅・卯・辰・巳・午・未・申・酉・戌・亥。
- 正規化上は9×12の108キーだが、資料内の典拠別本文を別レコードで保持する。
- 資料の例: 陽遁一局・丙辛日・辛卯時で値符星が天沖なら、`天沖×卯` を参照する。

### 典拠別レコード

資料は少なくとも次の2系列を載せる。

1. 『奇門遁甲秘笈大全』系
2. 『遁甲演義』系

同じ星×時支でも本文や対象用途が異なり得るため、`source_tradition` をキーの一部にする。後勝ち上書きは禁止。

### 必須データ項目

- `source_tradition`
- `value_star`
- `hour_branch`
- `heading_raw`（複数星をまとめた見出しを含む）
- `application_context`（作用後、葬後、入宅、安墳、上官、下穴等）
- `omen_body`
- `result_body`
- `time_to_result_raw`（日数、月数、年数等がある場合）
- `direction`（方位が本文に明示される場合）
- `person_or_name_sound`（姓名の五音が条件になる場合）
- `fortune_raw`（明示がある場合のみ）
- `notes`（語注・伝承説明）

### 表記・グルーピング例外

- 天沖は本文で「天衝（天沖）」と書かれる箇所がある。検索用正規値は `天沖` とし、`heading_raw` に原表記を残す。
- 一つの見出しに複数星が列記される箇所がある（例: 天蓬星・天芮星、天心星・天柱星等）。実装検索のため星ごとに展開してよいが、`group_id` と `heading_raw` で同一本文からの展開であることを保持する。
- 『奇門遁甲秘笈大全』は「作用後」と「葬後」を区別し、『遁甲演義』は主に「葬後」の剋應を扱う。用途を落とさない。
- 五音（宮・商・角・徴・羽）は姓名条件として現れる。外部の姓名判定を実装せず、資料本文の条件値として保存する。
- 本文中の民族伝承・故事・語注は、判定本文を理解するための注記であり、判定キーではない。
- 明示的な吉凶語がない本文を、結果の内容から自動分類しない。

## 7. 判定APIの責務

剋應モジュールは、既に算出済みの盤情報を入力として参照データを引くだけに限定する。

```text
十干:       heavenStem + earthStem
八門・静應: humanGate + (earthGate | heavenStem)
八門・動應: humanGate + earthGate
九星値時:   chiefStar + hourBranch + sourceTradition
三奇到宮:   wonderStem + palace
```

- 値符星、時支、天盤奇儀、地盤奇儀、人盤八門、地盤八門、宮は既存排盤結果から受け取る。
- 剋應モジュール内で暦計算・局計算・値符値使算出・九宮配置を再実装しない。
- データがない入力は推測せず `not_found` を返す。
- 複数典拠・複数条件に合致する場合は配列で全件返し、優先順位を勝手に付けない。

## 8. 実装前検証条件

1. 十干81キーが重複なく揃うこと。
2. 八門は3系列が混在せず、各レコードに静應/動應と相手種別が付くこと。
3. 九星値時は108の論理キーを基準に、典拠別・複数星見出し展開後も原文グループを復元できること。
4. 三奇到宮24キーが揃い、名称・吉凶・予兆・結果・時期が欠落しないこと。
5. 原文差・異説注記が単一数値に上書きされていないこと。
6. 変更差分が剋應モジュール以外にないこと。

## 9. 現時点の変更範囲

この整理では仕様抽出のみを行い、アプリコード、排盤ロジック、CalendarEngine、七政四餘、UIには変更を加えていない。
