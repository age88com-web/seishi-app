# 03. 超神接気・置閏

## 目的

奇門遁甲の暦（二十四節気 × 三元 × 五日 ＝ 360日を一年とする）と、実際の太陽暦（365.2422日）のズレを補正すること。

回帰テストは `tests/qimen_dingju_context.manual.ts`。

## 1. 用語【講義記載】

講義資料 p16 の本文:

> これまで述べたように、奇門遁甲では二十四節気×三元×五日（３６０）を一年として用いている。
> 実際の陽暦の一年では365.2422日であり、ズレが生じてしまう。
> そのズレによって、節気の切り替わる日の干支が「符頭」（上元の始まる日：甲子、甲午、己卯、己酉）と一致しない事がおこる。
> 符頭が節気より前に現れる：超神
> 符頭が節気より後に現れる：接気　　※節気と符頭が同じ日になる：正授
> 三年で15日ほどずれるため、そうすると一つの節気を超えてしまうので、修正が必要。　修正方法を置閏法という。

| 用語 | 定義 |
|---|---|
| 符頭 | 上元の始まる日。甲子・甲午・己卯・己酉 |
| 正授 | 符頭と節気が同じ日 |
| 超神 | 符頭が節気より前に現れる |
| 接気 | 符頭が節気より後に現れる。置閏を行った結果、符頭が二至の後になる状態も接気（「超神節気・置閏」） |

## 2. 置閏法【講義記載】

講義資料 p17 の本文:

> もし局の運行の最終から符頭までが夏至、冬至の9日以上前となる場合（超神）、ズレを修正するため閏を置く。
> 夏至の前：６局を5日、３局を5日、９局を5日
> 冬至の前：４局を5日、７局を5日、１局を5日
> （中略：例は §4）
> 必ず15日を閏としていれる

ここから確定する事項:

- 置閏は **夏至の前・冬至の前でのみ** 行う。他の節気では行わない。
- 置閏では **必ず15日**（上元・中元・下元 各5日）を入れる。
- 夏至の前は **陽六局・陽三局・陽九局**（芒種の三元の繰り返し）。
- 冬至の前は **陰四局・陰七局・陰一局**（大雪の三元の繰り返し）。
  - 冬至側は局配列だけが資料で確定している。**具体的な年月日の例は資料に無い。**
- 6・3・9 は局数表（p14）の芒種の行、4・7・1 は局数表（p15）の大雪の行とそれぞれ一致する。

## 3. 実装規則【実装規則】（ユーザー確定 2026-10-06）

講義の「9日以上前」は、日数の数え方（二至当日を含めるか）が本文から一意に決まらない。また日の境も講義資料に規定が無い。本プロジェクトでは次のとおり定める。

| 項目 | 採用した規則 | 理由 |
|---|---|---|
| 置閏の閾値 | **二至当日を差日数に含めず、符頭が二至の9日以上前にある場合に置閏する**（8日以下は置閏しない） | 1975年（5日、置閏なし）と1976年（10日、置閏）の講義例を矛盾なく再現できる。二至当日を含めて9日以上とする読み方では、1975年冬至（含めて9日）で置閏が起き、「1976年は6/10まで陽九局」「1976年6月が閏」という講義記載と矛盾する |
| 日の境 | **23:00**。節入り時刻が 23:00 以降なら、翌日の日干支の日として扱う | 本プロジェクトの占術上の基本ルール。CalendarEngine の既存の 23:00 切替をそのまま使う |
| 節入り日 | 節入り時刻の時点の日干支の日（上記 23:00 境界を適用） | p16「節気の切り替わる日の干支」 |

## 4. 講義資料の例【講義記載】

各日の日干支は、CalendarEngine の計算値とすべて一致している。

### 1974年：正授

- 1974年6月22日 夏至。この日は甲午で、その日自体が符頭 → **正授**。

### 1975年：超神・置閏なし（p17）

> Ex）1975年６月22日己亥　　6月17日甲午　符頭が夏至の前＝超神
> ただし17日から22日だと6日なので置閏ではない.

- 夏至 6/22（己亥）、符頭 6/17（甲午）→ **超神**。
- 講義は「17日から22日だと6日」と数えている（二至当日を含めた数え方）。二至当日を含めない差日数は5日。どちらの数え方でも9日未満 → **置閏しない**。

### 1976年：置閏（p17・「超神節気・置閏」）

> 1976年6月21日甲辰　　6月11日甲午　符頭が10日前なので閏が必要
> 15日の修正を入れる。（芒種）
> 6月11日から15日陽六局、16日から20日陽三局
> 21日から25日陽九局とし、この年の夏至は26日

- 夏至 6/21（甲辰）、符頭 6/11（甲午）。差日数は二至当日を含めず10日（「超神節気・置閏」では「夏至の日を含め11日」）→ 9日以上 → **置閏**。
- 陽遁最後の陽九局は **6月10日で終了**（「超神節気・置閏」）。
- 置閏期間（芒種の三元を繰り返す）:

| 期間 | 局 |
|---|---|
| 6月11日〜15日 | 陽六局 |
| 6月16日〜20日 | 陽三局 |
| 6月21日〜25日 | 陽九局 |
| **6月26日から** | **陰九局** |

- **実際の天文上の夏至は 6/21（15:15 JST）だが、定局上は 6/25 まで陽遁を継続する。**

### 1979年：接気

- 1979年6月22日 夏至。符頭は 6月26日の甲子。符頭が夏至より後 → **接気**。

## 5. 判定方法（`dingjuContext.ts`）

### 5-1. 天文上の節気と定局節気の分離

```
CalendarEngine.calculate()        天文上の節気・節入り時刻・干支（変更しない）
        ↓
resolveDingjuContext()            正授・超神・接気・置閏の判定 → 定局用節気
        ↓ effectiveSolarTerm
resolveDingju()（dingju.ts）       陰陽遁・三元・局数（変更しない）
        ↓
地盤以降の排盤                     （変更しない。1080局テストの範囲）
```

`QimenDingjuContext` は両方の値を同時に保持する。

| 区分 | フィールド | 内容 |
|---|---|---|
| 天文上の値 | `actualSolarTerm` / `actualSolarTermDateTime` / `actualDun` | CalendarEngine の値をそのまま写す |
| 定局上の値 | `effectiveSolarTerm` / `effectiveDun` / `effectiveYuan` / `effectiveJu` | 超神・接気・置閏を反映した値。排盤はこちらを使う |
| 関係 | `relation`（正授 / 超神 / 接気）・`relationDays`・`actualSolarTermDate`・`futouDate` | **その日の天文上の節気**について、節入り日と定局上の上元符頭を比べたもの。超神は正、接気は負の日数 |
| 置閏 | `isLeapAdjustment`・`leap`（二至・繰り返す節気・期間） | 対象日が置閏期間に入っているか |

`qimenEngine.calculate()` の結果では、`dingju` が定局上の値、`dingjuContext` が上記の詳細、`calendar.solarTerm` は天文上の節気のままである。

例: 1976年6月22日 正午

| actualSolarTerm | actualDun | effectiveSolarTerm | effectiveDun | effectiveJu | isLeapAdjustment |
|---|---|---|---|---|---|
| 夏至 | 陰遁 | 芒種 | 陽遁 | 9 | true |

### 5-2. 二至の上元符頭（実装規則の適用）

二至 S の節入り日の日干支の 60干支番号を i（甲子 = 0）とすると、`r = i mod 15` は直前の上元符頭から S までの日数（二至当日を含めない）。

- `r = 0` → 正授。上元符頭 = S。
- `1 ≤ r ≤ 8` → 超神。上元符頭 = S の r 日前。
- `r ≥ 9` → 置閏。上元符頭 = S の (15 − r) 日後（接気）。

### 5-3. 対象日の定局節気

1. 対象日をはさむ二至の上元符頭 B_prev ≦ 対象日 < B_next を求める（前年夏至〜翌年夏至の二至から選ぶ）。
2. 間隔 `B_next − B_prev` は 180日（12節気 × 15日）か 195日（＋置閏15日）。それ以外なら例外を投げる。
3. `k = floor((対象日 − B_prev) / 15)`:
   - `k ≤ 11` → 二至から数えて k 番目の節気（二十四節気の順序は CalendarEngine の `SOLAR_TERMS`）。
   - `k = 12`（間隔195日のときだけ）→ 置閏期間。次の二至の直前の節気（芒種 / 大雪）を繰り返す。
4. 定局用節気と日干支を既存の `resolveDingju()` に渡す。三元はこれまでどおり日干支の符頭で決まる。

整合性チェック（不一致なら例外）:

- `resolveDingju()` の三元と、上元符頭からの位置（0〜4日目 上元／5〜9日目 中元／10〜14日目 下元）が一致すること。
- 置閏期間の局が講義の局配列（夏至前 6・3・9／冬至前 4・7・1）と一致すること。

この局所判定は、「前の二至の上元符頭 + 180日を候補とし、候補が二至の9日以上前なら15日を閏として入れる」を逐次適用した結果と一致する。正授の起点を何年も遡って探す処理は持たない。
