# 08. 八門

## 目的

値使を割り出し、九宮それぞれに八門（休門・生門・傷門・杜門・景門・死門・驚門・開門）を配置すること（人盤）。

## 実装状況（2026-09-02 時点）

**実装済み。** `src/lib/qimen/bamen.ts` の `resolveBaMen({ diPan, dun, liuyi, xunShou, hourStem, hourBranch })`。
（旧仕様書は「未実装」、かつ定位表・方向規則に誤りがあった。以下は `docs/source/奇門遁甲講義案八門.pdf`（28〜31ページ）を最優先として全面的に書き直したもの。）

### 今回実装で確定した事項

- **八門の定位**（`BAMEN_NATAL_POSITION`、中宮は無位）：

  | 巽4 杜門 | 離9 景門 | 坤2 死門 |
  |---|---|---|
  | 震3 傷門 | 中5 （無位） | 兌7 驚門 |
  | 艮8 生門 | 坎1 休門 | 乾6 開門 |

- **手順**（28〜29ページの実例＝上元丙寅日・辛卯時・陽一局 から再構成、実例図と完全一致）：
  1. ② 地盤上で liuyi が置かれた宮 `P_liuyi` を求め、その宮の定位八門が**値使**。
  2. ③ 旬首の干支から用事の時干支まで、六十干支の順を1から数える（旬首自身を1）。
     `count = ((hourIndex - xunShouIndex) % 60 + 60) % 60 + 1`
  3. ④ 値使の宮 `P_liuyi` から、陽遁は順行（`+1`）・陰遁は逆行（`-1`）で `(count-1)` 歩だけ洛書数を進めた宮が**値使の実際の位置** `zhishiPalace = mod9(P_liuyi + direction*(count-1))`。
  4. ⑤ 値使が定位から実際の位置へ移動したのと同じ向き・歩数だけ、環 `RING = [4,9,2,7,6,1,8,3]` 上で残り7門も一斉に移動する。
     `delta = mod8(ringIndexOf(zhishiPalace) - ringIndexOf(P_liuyi))`
- 戻り値：`{ zhishi: { men, palace }, baMen: Record<1..9, BaMenName[]> }`。中宮は常に空配列。
- **確定例**（陽一局・辛卯時。旬首 甲申（idx20）、辛卯（idx27）、`count = 7+1 = 8`、`P_liuyi = 3`、陽遁 `+1`）：
  `zhishiPalace = mod9(3 + 7) = 1`、値使 ＝ `NATAL[3] = 傷門`（＝ 傷門@1宮）。`delta = ringIndexOf(1)-ringIndexOf(3) = 5-7 → mod8 = 6`。

  | 宮 | 坎1 | 坤2 | 震3 | 巽4 | 中5 | 乾6 | 兌7 | 艮8 | 離9 |
  |---|---|---|---|---|---|---|---|---|---|
  | 八門 | 傷門 | 開門 | 景門 | 死門 | － | 生門 | 休門 | 杜門 | 驚門 |

  （`10_排盤完成.md` の完成盤資料と9宮完全一致。）

### 講義資料の誤読を修正した事項

- **八門の定位表が誤っていた。** 旧仕様書の定位（巽4死門／離9驚門／坤2開門／震3景門／兌7傷門／艮8杜門／坎1休門／乾6生門）は、正しい定位の**対宮（環の反対側）にずれた**ものだった。正しくは上表（1休 2死 3傷 4杜 6開 7驚 8生 9景）。`docs/source/奇門遁甲講義案八門.pdf` で確定。
- **回転方向が逆だった。** 旧仕様書は「④値使の宮から順飛（陽遁は逆行、陰遁は順行）」としていたが、正しくは**陽遁＝順行（+1）／陰遁＝逆行（-1）**（地盤 `dipan.ts` と同じ向き）。
- `10_排盤完成.md` の「訂正履歴」に既述の通り、旧完成盤サムネイルの八門配置も誤っており、`bamen.ts` の導出結果（＝正しい完成盤資料）が正。

### TODO として残した事項（`bamen.ts` 内のコメントと一致）

- **例外1（六儀＝liuyi の宮が中宮になる場合）**：実装済み。坤宮(2)を「代用の liuyi の宮」として扱い、以降②③④⑤を通常どおり進める（＝`P_liuyi` を2として計算するのと等価）。ただしこの寄せ先が坤宮でよいかは講義資料本文の文章から一意に決めたもので、実例図での裏付けは無い。
- **例外2（時干が中宮になる場合）**：八門の算出式（②③④⑤）は「時干の宮」そのものを数値として使っていない（使うのは旬首と用事の時刻の干支差、および `P_liuyi` のみ）。そのため八門の計算には影響せず無処理でよい、と判断している。時干の宮の妥当性チェック（地盤に時干が存在すること）は行うが、中宮であることを理由にはエラーにしない。
- **時干が甲のとき**：地盤に甲が無く `hourStem` の宮が求まらないため例外を投げる（`qimenEngine` 側で八門の段のみ `null` として扱う）。
